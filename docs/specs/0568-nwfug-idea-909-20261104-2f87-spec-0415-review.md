## Context

[SPEC-0415](./0415-campaign-history-fixture-spec-0405-child.md) (done) shipped
`tools/capture_history_fixture.py` and `tests/test_history_fixture.py`. Its review left six
minor findings (follow-up idea IDEA-1010, from IDEA-909):

1. **Bare-word user-name rule over-rewrites.** `Sanitizer.__init__` builds `user_res` from the
   `users` set (`$USER`, `Path.home().name`, the `--src` owner) as whole-word regexes
   (`tools/capture_history_fixture.py:75`), and `Sanitizer.text` rewrites every match in every
   string to `user`. When the account name is a dictionary word (`runner`, `root`, `dev`,
   `admin`), real text such as "the runner log" becomes "the user log" in the committed fixture.
2. **Unrelated test files in the branch diff.** The SPEC-0415 branch also edited
   `tests/test_dashboard_auth.py`, `tests/test_dashboard_server.py`,
   `tests/test_tui_queue_parity.py` and `tests/test_tui_queue_view.py`, which the spec's
   Non-goals ("no production or unrelated changes") excluded. Those edits have already merged
   with their own fixes; they cannot be undone by a new spec.
3. **AC10's 20 s bound is unenforced.** The "under 20 s" runtime of
   `tests/test_history_fixture.py` is recorded only in the spec's test record (about 5 s); no
   test fails when it is exceeded.
4. **Same as 3** (two reviewers filed it): nothing at session level enforces the budget.
5. **A test mutates the shared captured source.** `test_sanitization_redacts_and_verifies`
   (`tests/test_history_fixture.py:454`) overwrites `spec_at_open.md` in the module-scoped
   `captured["src"]` and restores placeholder content, not the original bytes. A later test on
   the same worker that reads that file sees different content.
6. **Unchecked path components.** In `collect_records` the `spec_id` and `project` values come
   from the source `state.json` and are joined into read paths: `rv / str(s)`
   (`:573`) and `sd / f"{proj}.last.json"` (`:598`), and the second becomes
   `files["sentinel/{proj}.last.json"]`, later written under the output tmp dir. A value with
   `../` or a leading `/` reads files outside `agentic/reviews` / `agentic/sentinel` and writes
   outside the output tree.

## Goals / Non-goals

**Goals**
- A dictionary-word account name no longer rewrites ordinary prose in the fixture, while no
  user-identifying path segment survives.
- The capture tool reads and writes only inside the source `agentic/` tree and the output tree,
  whatever `state.json` holds.
- The 20 s budget of `tests/test_history_fixture.py` is enforced by the module itself.
- No test in that module leaves the shared captured source changed.

**Non-goals**
- Reverting the dashboard/TUI test edits (finding 2): they landed with their own
  justification; this spec only guarantees that its own change touches no file outside
  `tools/capture_history_fixture.py`, `tests/test_history_fixture.py` and this spec.
- Changing any production module under `src/nightwright/`.
- Re-capturing or changing the committed fixture `tests/fixtures/agentic_history/`: its hashes
  and `MANIFEST.json` stay as they are, and `--check` must keep passing unchanged.
- Changing the rules for hosts, IPs, emails, secrets or `env`.

## Decision

1. **Common-word names become path-segment-only.** A name in a fixed `COMMON_WORD_USERS` set
   (`root`, `runner`, `dev`, `admin`, `ubuntu`, `debian`, `build`, `ci`, `test`, `worker`,
   `agent`, `deploy`, `github`, `jenkins`, `docker`, `service`, `nobody`, `ec2-user`) keeps the
   path rule only: `/<name>` followed by a non-word character is rewritten to `/user`, which
   is the same pattern `scan` uses for `user_segment`, so the scan still passes. Every other
   name keeps the existing bare-word rule. Names are never lowercased or fuzzy-matched.
2. **No action on finding 2**, other than the file-set guarantee in the Non-goals, recorded as
   an acceptance criterion checked against the diff.
3. **The 20 s budget is a module-level guard.** The module sums the wall time of each of its
   tests (plus the module-scoped `captured` capture) and fails the module at teardown if the
   sum exceeds `HISTORY_FIXTURE_BUDGET_S` (20.0; the env var `NW_HISTORY_FIXTURE_BUDGET_S`
   overrides it for a slow box). It sums per-test time instead of module wall time so
   `pytest-xdist` interleaving with other modules cannot inflate it.
4. **Mutating tests work on a copy.** `test_sanitization_redacts_and_verifies` copies
   `captured["src"]` into `tmp_path` and plants `CODENAME-HYDRA` there. The shared source is
   never written by a test, and a guard asserts that.
5. **Path components are validated before use.** `collect_records` accepts a `spec_id` or
   `project` only if it matches `^[A-Za-z0-9][A-Za-z0-9._-]*$` and is not `.`/`..`; otherwise
   it skips that value with a `note(...)` line and reads nothing for it. Every file it would
   read from `reviews/<spec_id>/` and `sentinel/` must also resolve (symlinks followed) to a
   path inside the resolved source `agentic/` directory, or it is skipped with a note. Output
   keys are built only from validated values.

## Design

**`tools/capture_history_fixture.py`**
- Add `COMMON_WORD_USERS` next to the sanitization constants and `SAFE_NAME_RE`
  (`^[A-Za-z0-9][A-Za-z0-9._-]*$`).
- `Sanitizer.__init__`: build `user_res` per user: a path-segment regex
  `/<name>(?![\w.-])` (replacement `/user`) for names in `COMMON_WORD_USERS`, the existing
  whole-word regex (replacement `user`) otherwise. Store pairs `(regex, replacement)`; the
  loop in `text` uses them and keeps counting under `user_name`. The `len(u) >= 3` and
  `u != "user"` filters are unchanged.
- `scan` is unchanged: its `/name(?![\w.-])` segment regex already covers what the common-word
  rule rewrites.
- `collect_records`: a small helper `_safe_name(v) -> bool` and `_inside(path, root) -> bool`
  (`path.resolve().is_relative_to(root.resolve())`). Apply `_safe_name` to each `spec_id` in
  `specs` before `rv / str(s)`, and to each `proj` before `sd / f"{proj}.last.json"`. Apply
  `_inside(f, agentic)` to each file from the `rglob` and to the sentinel file. Skips call
  `note(f"unsafe spec_id {s!r}: skipped")` / `note(f"unsafe project {proj!r}: skipped")`.
  The tool stays stdlib-only (`test_tool_imports_only_stdlib`).

**`tests/test_history_fixture.py`** (existing module, already
`pytestmark = pytest.mark.integration`; no new module and no second marker)
- Module-level `_SPENT = [0.0]` and `HISTORY_FIXTURE_BUDGET_S`; a function-scoped autouse
  fixture adds each test's elapsed time (`time.monotonic()` around `yield`); the `captured`
  fixture adds its own capture time. A module-scoped autouse fixture asserts
  `check_budget(_SPENT[0], budget)` after `yield`; `check_budget` raises `AssertionError`
  with the measured and allowed seconds when over.
- `test_sanitization_redacts_and_verifies`: `src2 = tmp_path / "src2"`;
  `shutil.copytree(captured["src"], src2)`; plant and run against `src2`; drop the `try/finally`
  restore.
- A `tree_digest(src)` helper (sha256 over sorted relative paths and bytes) is taken in the
  `captured` fixture and re-checked by the module-scoped teardown, failing if the shared
  source changed.
- New tests listed in the Test plan.

## Alternatives considered

- **Skip the user-name rule entirely for common words** — a home path outside `/home/<name>`
  such as `/srv/runner/x` would then stay and `scan` would flag `user_segment`, failing the
  capture; keeping the path-segment form is both safe and consistent.
- **Detect "dictionary word" with a word list** — a new dependency or data file for a
  six-line problem; a fixed stoplist of common account names is deterministic and reviewable.
- **A global pytest plugin or `conftest.py` timer for the budget** — affects every module; the
  budget concerns this module only.
- **Fail the capture on an unsafe `spec_id`/`project`** — one hostile or corrupt campaign
  should not block the capture of the others; skip and note.

### As shipped (2026-11-12)

- `COMMON_WORD_USERS` = `root runner dev admin ubuntu debian build ci test worker agent deploy github
  jenkins docker service nobody ec2-user`, as decided. `SAFE_NAME_RE`, `_safe_name` and `_inside` are in
  the tool; skipped values emit `unsafe spec_id ...`/`unsafe project ...` notes, and a review file that
  resolves outside `agentic/` emits a `... resolves outside agentic/: skipped` note. `None` spec_ids and
  projects are skipped silently (as before); an empty string is an unsafe name and is noted.
- Budget guard: per-test autouse timer, the `captured` capture time, module-scoped teardown calling
  `check_budget`; the source digest is checked in the `captured` fixture's teardown.
- Deviation (runtime, no behaviour change): with the budget enforced, the module took 30 s+ because
  `EMAIL_RE` and `TAIL_EMAIL_RE` are quadratic on long local-part-like runs (60 000 chars: 8 s / 25 s).
  The tool now uses `sub_emails` (find each `@domain`, extend the local part backwards; output is
  identical to `EMAIL_RE.sub`, checked against it on 200 000 random strings) in `Sanitizer.text`, and
  `trim_cut` finds the only possible cut email at the last `@` (checked against the old regex on
  100 000 random strings). `EMAIL_RE` and `scan` are unchanged, and the committed fixture is
  byte-identical.
- The module's summed test time is around 15 s on a loaded box; `NW_HISTORY_FIXTURE_BUDGET_S` is the
  override for a slower one.
