## Context

[SPEC-0526](./0526-nw-campaign-run-id-run-crashes-with-a-rich-markup.md) made
`nw campaign run <campaign> <run>` survive bracketed verdict text. `_print_run` in
`src/nightwright/agentic/cli_campaign.py` now wraps every stored value in
`rich.markup.escape` and puts it into an f-string markup line, for example
`console.print(f"  [dim]{key:<14}[/] {escape(str(value))}", highlight=False)` in `kv()`. The
header line does the same with the run id, campaign, verdict status, source and status. Two
review findings on that change were left open (IDEA-1128, the SPEC-0526 review).

1. **A field that ends in one backslash is printed with two.** `rich.markup.escape` appends an
   extra backslash when its result ends in a single `\`, so that a following markup tag stays a
   tag. `kv()` puts the escaped value at the end of the markup string, where nothing follows,
   and the unstyled verdict status is placed the same way. Checked against Rich: a value `ab\`
   comes out as `ab\\`. A path, error tail or summary that ends in `\` is therefore displayed
   wrong. The run record is stored data; the human view must show it as it is.
2. **The tests check text, not styling.** SPEC-0526's Decision keeps bold on the run id, dim on
   the field labels, and a verdict color only when `_VERDICT_STYLES` has an entry, and it
   rejects `markup=False` because that drops those tags. The new tests in
   `tests/test_agentic_campaign_runs.py` (`test_run_human_view_prints_bracketed_verdict`,
   `test_run_human_view_prints_unstyled_verdict_status`) only look for substrings in plain
   output. A change that dropped bold, dim or the verdict color would still pass them.

## Goals / Non-goals

**Goals**

- Every value `_print_run` shows (run id, campaign, verdict status, source, status, and every
  `kv()` value) is displayed byte-for-byte, including values that end in one or more
  backslashes, and still never raises `MarkupError` on bracketed text.
- The styling SPEC-0526 promised stays: bold run id, dim field labels, green or red or dim
  verdict color only for statuses present in `_VERDICT_STYLES`, no style for other statuses.
- Tests assert that styling, not only the text.

**Non-goals**

- No change to the `--json` output, `nw campaign runs`, `_print_story`, or the field set and
  layout of the human view.
- No change to `_VERDICT_STYLES` or to how `verdict_status` is derived.
- No change to the stderr tail lines, which already use `Text`.

## Decision

Build the lines of `_print_run` from `rich.text.Text` objects, not from markup strings. Values
go in as literal text, so nothing parses them and nothing needs `escape`. Styles are attached
to the spans that carry them. This removes the whole class of escaping bugs (including the
trailing-backslash doubling) instead of patching `escape`'s output, and it matches how the
`nw campaign runs` table and the stderr tail already render stored text. Add tests that render
`_print_run` to a color terminal and assert the ANSI styling and the verbatim values.

## Design

**Rendering (`src/nightwright/agentic/cli_campaign.py`)**

- `kv(key, value)` prints
  `Text.assemble("  ", (f"{key:<14}", "dim"), " ", str(value))` with `highlight=False`. The
  value is a plain `str` argument, which `Text.assemble` appends without markup parsing.
- The header prints `Text.assemble((str(rec["run_id"]), "bold"), "  ", str(rec["campaign"]),
  "  ", (str(vs), style), "  (", str(rec["source"]), ", ", str(rec["status"]), ")")`
  where `style = _VERDICT_STYLES.get(vs, "")`. An empty style string adds no style, so an
  unmapped status prints plain, as before.
- The `stderr tail` label becomes `Text("  stderr tail", style="dim")` so no markup string
  remains in `_print_run`.
- The `rich.markup.escape` import is removed if no other use of it remains in the module.
- Visible layout is unchanged: same spacing, same label padding to 14 columns, same order of
  fields.

**Tests (`tests/test_agentic_campaign_runs.py`)**

The module already carries `pytestmark = pytest.mark.fast`; no second tier marker is added.
New tests call `cli_campaign._print_run(rec)` directly with `rec` from
`RN.campaign_run(cfg, cid, run)` (the same record `campaign run` prints), after replacing
`nightwright.agentic.cli_campaign.console` with
`Console(file=io.StringIO(), force_terminal=True, color_system="standard", width=250)` through
`monkeypatch.setattr`, so the captured output carries ANSI escapes.

- Styling test: for a run whose verdict status is `done`, the output has the run id preceded
  by the bold code `\x1b[1m`, each field label (`persona`, `started`, `exit`, `cost`)
  preceded by the dim code `\x1b[2m`, and the status `done` preceded by green `\x1b[32m`. A
  `blocked` run has red `\x1b[31m` before the status.
- Unstyled-status test: for statuses `fix` and `?`, the status text appears with no color
  code immediately before it (no `\x1b[3Xm` between the two spaces around it), and bold and
  dim are still present on the run id and labels.
- Trailing-backslash test: a summary, a `must_fix` item, an error tail and a path value that
  each end in one backslash, and a verdict status ending in one backslash, print with exactly
  one trailing backslash (stripping ANSI codes, the line ends in `x\` and not `x\\`); a value
  with an even run of backslashes keeps its count.
- The existing bracketed-text tests stay and still pass.

## Alternatives considered

- **Keep markup, strip the doubled backslash by hand** — fragile: it depends on Rich's
  internal escape rule and still leaves markup parsing on stored text.
- **`markup=False` on the console call** — rejected by SPEC-0526: it prints the structural
  tags (`[bold]`, `[dim]`) literally.
- **Use `Text.from_markup` for the labels and `Text(value)` for values** — works, but needs
  no markup at all once the styles are given as spans, so it adds parsing for nothing.
- **Leave the test finding to snapshot tests of the whole output** — heavier and brittle on
  width and Rich version; targeted ANSI code checks are enough.

## Acceptance criteria

- [ ] `_print_run` builds its output from `Text` and contains no f-string markup tags
      (`[dim]`, `[bold]`, `[/]`) and no call to `rich.markup.escape`.
- [ ] A summary, `must_fix` item, blocker, error tail, denial and path value ending in one
      backslash is printed with exactly one trailing backslash; so is a verdict status.
- [ ] Bracketed values (`[/bold]`, `[x]`, `[/dim]`, `[link]`) still print intact and the
      command exits 0.
- [ ] On a color terminal the run id is bold, each `kv` label is dim, and a status in
      `_VERDICT_STYLES` carries its color; a status not in the map (`fix`, `?`) carries no
      color.
- [ ] `nw campaign run --json`, `nw campaign runs` and the stderr tail output are unchanged.
- [ ] The new tests fail against the SPEC-0526 implementation (the backslash test) and pass
      against this one; the styling tests fail if bold, dim or the verdict color is removed.

## Test plan

- **Automated tests:** extend `tests/test_agentic_campaign_runs.py` (fast tier, marker
  already present; no new test module) with the styling test, the unstyled-status test and
  the trailing-backslash test described in Design, using the `merged` fixture and `add_run`
  helper. Run
  `python3 tools/affected_tests.py --run uv run pytest -q` plus
  `uv run pytest -q tests/test_agentic_campaign_runs.py`.
- **Tier check:** `python3 tools/test_tiers.py --check` exits 0 (no new module, so no new
  marker).
- **Manual verification:** in a campaign, `nw campaign run <campaign> <run>` on a run whose
  stored verdict summary ends in `C:\dir\` shows `C:\dir\` once and the header keeps bold id
  and the status color on a terminal.
- **Regression guard:** the existing SPEC-0526 tests
  (`test_run_human_view_prints_bracketed_verdict`,
  `test_run_human_view_prints_unstyled_verdict_status`, `test_run_json_keeps_bracketed_verdict`),
  `test_run_detail`, `test_run_detail_must_fix_and_blockers` and `test_human_views_render`
  pass unchanged; `python3 tools/spec_lint.py` exits 0.
