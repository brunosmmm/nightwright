## Context

[SPEC-0299](./0299-conductor-cost-measurement.md) shipped the conductor session registry,
`wt queue conductor-cost` and the `conductor_usd` / `cost_with_conductor_usd` export columns
(`src/wt/agentic/conductor_cost.py`, `cli_conductor.py`, `campaign_export.py`). It merged
with a review score of 90 and left 21 minor findings, filed as follow-up IDEA-408 (10 listed
and 11 capped; several are the same defect seen by two reviewers). After its own review
round, SPEC-0299 already covers some of them (session ids with glob characters never match a
transcript, a price with a non-numeric value is treated as no price, the window-edge and
`created_at` fallback tests exist, and the `conductor-session list` text rows are tested).
What is still open falls into four groups:

1. **A terminal campaign with no terminal transition stays live forever.** `live_windows`
   takes `end` only from a `transition` event whose `to` is in `store.TERMINAL_STATES`.
   A campaign whose `state.json` is `MERGED` / `HANDED_OFF` / `ABANDONED` but whose ledger has
   no such event (a legacy campaign, or a hand-repaired one) gets `end = None`, and
   `_live_at` reads that as "still live". It then absorbs an equal share of every conductor
   turn from its start to the present. `campaign_export.campaign_row` treats the same
   campaign as ended (`end = None` for a terminal state, so `wall_s` is not open-ended), so
   the two disagree.
2. **Measurement can still break `wt campaign export`.** `price_for` guards each price entry
   but assumes `agentic.conductor` is a dict and `prices` is a mapping; a config of
   `conductor: [1]` or `prices: "x"` raises. `price_for` also accepts `NaN` and `Infinity`
   (they are `float`), which reach the JSON output. `sessions()` reads `sessions.jsonl` with
   strict UTF-8, so one corrupted byte raises `UnicodeDecodeError` in `attribute()`.
   `export_tables` calls `conductor_cost.attribute` with no guard, so each of these fails an
   export whose conductor columns are a best-effort extra. Also, `find_transcript` and
   `subagent_transcripts` still feed session ids into `Path.glob`.
3. **Whole transcripts are read into memory on every export.** `read_turns` and
   `transcript_marks` do `read_text().splitlines()` and `json.loads` every line, including
   `--project` or `--since` filtered exports. The 5-day conductor transcript is hundreds of
   MB; the tool results and user lines it holds are never used.
4. **Record and test gaps.** SPEC-0299's Definition of done ticks "manual steps performed",
   and its Test plan expects about 2,386 turns, 1.09B cache reads and about $263, but As
   shipped records only the token half (2,405 turns, 1,096,983,054 cache reads); the dollar
   half needs `agentic.conductor.prices`, which is rollout step 2. The box is ticked without
   that caveat. Tests miss: a mixed priced/unpriced case with campaigns (`idle_usd` is
   checked, no campaign share or export column is), the `--reader` option through the CLI,
   the text forms for no session / a missing transcript, the `(partial: N unpriced turns)`
   suffix through the CLI, and non-finite prices.

## Goals / Non-goals

**Goals**
- A terminal campaign never absorbs conductor spend after it ended, whether or not its ledger
  has a terminal transition; `live_windows` and `campaign_row` agree on what "ended" means.
- `wt campaign export` and `wt queue conductor-cost` never fail because of the shape of
  `agentic.conductor`, the content of a price, or the bytes of `sessions.jsonl` or a
  transcript. The worst outcome is empty or partial conductor columns.
- Transcript reads are streaming, keep memory at the size of the parsed turns, and skip lines
  that cannot be turns before parsing JSON.
- SPEC-0299 tells the truth about the manual check: the dollar half is marked pending, with a
  recorded way to close it.
- The test gaps above are closed.

**Non-goals**
- No change to the `wt.conductor.cost.v1` payload, the export column names, order or types,
  or the equal-split attribution rule.
- No on-disk cache or index of transcripts. A per-process cache would not help a CLI run, and
  an on-disk one is a new durable artefact the MVP does not need.
- No change to how merges are counted: a campaign with no terminal transition event has no
  date to place it by, so it still is not counted as an ended or merged campaign in the
  report (as `campaign_row` leaves `ended_at` empty).
- Running the dollar half of the manual check: it needs the user's price configuration
  (SPEC-0299 rollout step 2), which this spec does not own.

## Decision

Fix the four groups inside the existing modules, without changing any output contract:

1. `live_windows` gains a separate `live_end` per campaign, used only by `_live_at`. It is
   the terminal transition's time when there is one. For a campaign in a terminal state
   with no such transition it is `max(start, min(updated_at, last_transition_ts))`, where
   `last_transition_ts` is the time of the last `transition` event of any kind: `updated_at`
   alone is rewritten by every save of the state, so a campaign repaired into `MERGED` weeks
   after it ended would otherwise keep absorbing until the repair. When only one of the two
   parses, that one is used; when neither does, `start` (a zero-length window that absorbs
   nothing).
   For a campaign not in a terminal state it is `None` (still live). `end` and `outcome`
   keep their meaning and values, so merge counting is unchanged.
2. Config and file reads are made total. `price_for` tolerates any shape and rejects
   non-finite or negative prices. `sessions()` decodes with `errors="replace"`. Transcripts
   are found by exact path lookup, never a glob. `export_tables` wraps `attribute` so any
   failure leaves the conductor columns empty (`None`), as when no session is registered.
3. `read_turns` and `transcript_marks` iterate the file object line by line and parse JSON
   only for lines that can matter.
4. SPEC-0299's DoD line and manual-verification item are amended to say "token half only", and
   its As shipped gets a pending-item note for the dollar half. The missing tests are added.

## Design

**Live end (`conductor_cost.py`).** `live_windows` returns, per campaign, the existing keys
plus `live_end`. The state's `updated_at` is parsed with `_parse_ts`. It is written by
`store.py:203` (`now_iso()`) on every save, so it is only an upper bound for a terminal
campaign: any later save (a cost or close backfill, a note, a hand repair) moves it. The
tighter bound is the `ts` of the last `transition` event of any kind, which `live_windows`
already reads (`types=["open", "transition"]`), so it costs no extra ledger read. Rules, in
order:

| State of the campaign | ledger has terminal transition | `live_end` |
|---|---|---|
| any | yes | the transition's `ts` (as `end` today) |
| in `store.TERMINAL_STATES` | no | `max(start, min(updated_at, last_transition_ts))`; when only one of `updated_at` / `last_transition_ts` parses, that one; when neither parses, `start`; if `start` is also `None` the window is never live (already so in `_live_at`) |
| not terminal | no | `None` |

`_live_at` tests `t < w["live_end"]` instead of `w["end"]`. `cost_report` keeps using `end`
and `outcome` for `ended`, `merged`, `by_day[*].merges` and `persona_usd`, so those figures do
not change. The docstring of `live_windows` names `live_end` and says why the two differ.

**Total config reads.** A helper `_conductor_cfg(cfg) -> dict` returns
`cfg["agentic"]["conductor"]` when each level is a dict, else `{}`; `price_for` uses it and
treats a non-mapping `prices` as `{}`. `_valid_price` additionally requires
`math.isfinite(v)` and `v >= 0` for each present kind, so a bad price makes the model
unpriced (existing behaviour for malformed entries) and `NaN` / `Infinity` never reach a USD
figure. `sessions()` reads with `errors="replace"` and returns what it parsed if the read
raises `OSError`. `find_transcript` and `subagent_transcripts` stop using `Path.glob` for
the session id: they list the direct children of `_root` and check
`<child>/<sid>.jsonl` (`is_file`) and `<child>/<sid>/subagents/**/*.jsonl` (the glob there
runs under a fixed, already existing directory and the `**` part carries no user input).
`_safe_id` stays as the first check and also rejects `.` and `..`.

In `campaign_export.export_tables`, the call becomes:

```python
try:
    shares = conductor_cost.attribute(cfg, now)
except Exception:        # measurement is an extra column set; it must not fail an export
    shares = None
```

and a one-line warning goes to stderr when it fails (`conductor columns skipped: <error
class>`), so a broken measurement is visible but not fatal. `wt queue conductor-cost` is
unchanged: it already surfaces errors from its own run.

**Streaming reads.** `read_turns` and `transcript_marks` open the file with
`open(path, encoding="utf-8", errors="replace")` and loop over it. Before `json.loads`, a
line is skipped unless it contains the substring `"assistant"` (turns) or `"assistant"` /
`compact_boundary` (marks); the substring test is spacing-independent and cheap, and the
parsed record is still checked as today (`type == "assistant"`), so a false positive costs
one parse and nothing else. An `OSError` mid-read returns the turns read so far (it was `[]`
for an unreadable file; an unreadable file still gives `[]`). Memory is the dict of parsed
turns, not the file text. The result of `read_turns` for a given file is byte-for-byte what
it is today.

**Docs (SPEC-0299).** The implementer edits `docs/specs/0299-conductor-cost-measurement.md`
only in these places, without changing its status or any other sentence:
- Definition of done: `- [x] Test plan executed; automated tests pass (uv run pytest);
  manual steps performed (token half only; the dollar half is pending rollout step 2).`
- Test plan, *Manual verification*: append "The dollar half runs once `agentic.conductor.prices`
  is set (rollout step 2); until then only the token half is recorded."
- As shipped: append "Pending: the dollar half. When prices are set, run `wt queue
  conductor-cost --since 2026-10-25 --until 2026-10-30` and record turns, cache reads and USD
  here; SPEC-0321 does not run it."

**Tests.** Added to `tests/test_agentic_conductor_cost.py` and
`tests/test_agentic_campaign_export.py`; names are given in the Test plan.

## Alternatives considered

- **Set `end` to the fallback time in `live_windows` and count such a campaign as ended.**
  It would also make `merges` and `by_day` count it, which `campaign_row` does not (no
  `ended_at`), and would move E1's denominator. A separate `live_end` fixes only the
  absorption.
- **End the window at the last ledger event of any type.** It needs a full ledger read per
  campaign (`live_windows` reads only `open` and `transition` today). The last `transition`
  is already in hand, and combined with `updated_at` (the cap) it bounds the window tightly.
- **Use `updated_at` alone.** It is rewritten on every save, so a hand-repaired campaign
  would keep absorbing until the repair, which is the defect being fixed.
- **Cache parsed turns per transcript (by path, mtime, size) on disk.** Faster repeat runs, but
  a new durable artefact to invalidate and migrate. Streaming plus the line pre-filter removes
  the memory problem, which was the finding, with no new state.
- **Validate `agentic.conductor` with a config schema.** A bad value already falls back to its
  default in the other `agentic.*` readers; a local type check in `price_for` does the same
  and needs no schema change.
- **Wrap `attribute` only in the CLI and not in `export_tables`.** The export is the only
  caller where failure is out of proportion to the feature.

## Acceptance criteria

- [ ] `live_windows` returns a `live_end` key for every campaign: the terminal transition's
      time when present; for a terminal-state campaign without one,
      `max(start, min(updated_at, last_transition_ts))` (the one that parses when only one
      does, `start` when neither does); `None` otherwise. `end` and `outcome` are unchanged.
- [ ] A conductor turn after a terminal-state campaign's `live_end` is attributed to no
      share of that campaign (it goes to the other live campaigns or to `idle_usd`), in
      `cost_report` and in `attribute`.
- [ ] A campaign in a terminal state with no terminal transition is not counted in `merges`,
      `by_day[*].merges` or `persona_usd`, and its `campaign_row` `ended_at` stays empty.
- [ ] `price_for` returns `None`, and never raises, when `agentic` or `agentic.conductor` is
      not a dict, when `prices` is not a mapping, and when a price kind is `NaN`,
      `Infinity` or negative.
- [ ] `sessions()` returns the parseable records of a `sessions.jsonl` that holds a non-UTF-8
      byte, and does not raise.
- [ ] `find_transcript` and `subagent_transcripts` do not call `Path.glob` with a session id,
      and still return the same files for ordinary ids; `.`, `..` and ids with a separator or
      glob metacharacter match nothing.
- [ ] `wt campaign export` exits 0 and leaves `conductor_usd` and `cost_with_conductor_usd`
      empty for every campaign when `attribute` raises, and prints exactly one
      `conductor columns skipped: <error class>` line on stderr. With a malformed
      `agentic.conductor` (e.g. `conductor: [1]`) it exits 0 with the columns empty and no
      warning; with a `sessions.jsonl` holding a bad byte it exits 0, prints no warning, and
      fills the columns from the parseable records.
- [ ] `read_turns` and `transcript_marks` read the file line by line (no `read_text` of the
      whole file) and return exactly what they returned before on every existing fixture.
- [ ] SPEC-0299's DoD line, Test plan manual item and As shipped carry the "token half only /
      dollar half pending" caveat, and no other part of SPEC-0299 changes.
- [ ] The tests in the Test plan exist and pass; each of the fault-injection checks makes its
      named test fail.
- [ ] `uv run pytest` and `python3 tools/spec_lint.py` pass.

## Test plan

- **Automated tests** (`tests/test_agentic_conductor_cost.py` unless noted; reuse the
  `campaign`, `write_transcript`, `turn` helpers):
  - `test_terminal_state_without_transition_stops_absorbing`: campaign `T` in state `MERGED`
    with an `open` event and no terminal transition, `updated_at` at 16:00; conductor turns
    at 15:00 and 18:00. Assert `live_end` is 16:00, the 15:00 turn is split with any other
    live campaign, the 18:00 turn lands in `idle_usd`, `end` is `None`, `merges == 0`.
  - `test_terminal_state_without_updated_at_gets_zero_length_window`: same, `updated_at`
    removed and no transition event besides `open`; assert `live_end == start` and the
    campaign gets a 0.0 share.
  - `test_terminal_state_without_transition_uses_last_transition_when_updated_at_is_late`:
    campaign in `MERGED` with a last (non-terminal) `transition` at 14:00 and `updated_at`
    days later; assert `live_end` is 14:00 and a 15:00 turn gives the campaign no share.
    A variant with an unparseable `updated_at` uses the 14:00 transition.
  - `test_non_terminal_without_transition_stays_live`: state `IMPLEMENTING`; `live_end` is
    `None` and the campaign takes shares to the end.
  - `test_live_window_agrees_with_campaign_row_for_terminal_without_transition`
    (`tests/test_agentic_campaign_export.py`): `campaign_row` has `ended_at` empty and a
    finite `wall_s`, and `live_windows` has `end None` with a finite `live_end`.
  - `test_price_for_tolerates_malformed_config_shapes`: `agentic` as a list, `conductor` as
    a list, `prices` as a string and as a list; each returns `None`.
  - `test_non_finite_and_negative_prices_mean_unpriced`: `NaN`, `inf`, `-1` as a kind value;
    `price_for` is `None`, `cost_report` JSON-serialises with `allow_nan=False`.
  - `test_sessions_survive_non_utf8_bytes`: write a valid record, a line with `b"\xff\xfe"`,
    another valid record; `sessions()` returns both records.
  - `test_export_survives_attribute_raising` (`tests/test_agentic_campaign_export.py`):
    `attribute` monkeypatched to raise `RuntimeError`; exit 0, both conductor columns empty
    for every campaign, stderr has exactly one `conductor columns skipped: RuntimeError`
    line; an unpatched run afterwards fills the columns.
  - `test_export_tolerates_malformed_conductor_config_and_bad_registry_byte`
    (`tests/test_agentic_campaign_export.py`): with `conductor: [1]`, exit 0, columns empty,
    no warning on stderr; with a `sessions.jsonl` holding a bad byte next to valid records
    that point at a priced transcript, exit 0, no warning, columns filled from the valid
    records.
  - `test_find_transcript_does_not_glob`: monkeypatch `pathlib.Path.glob` to raise; the
    lookup of an ordinary id still returns the file, `.` and `..` return `None`.
  - `test_read_turns_streams`: monkeypatch `Path.read_text` to raise; `read_turns` and
    `transcript_marks` still return the fixture's turns and marks. A fixture also holds large
    `user` / `tool_result` lines and `"assistant"` in a user message's text; the result
    equals the turn list expected from the assistant lines only.
  - `test_mixed_priced_unpriced_with_live_campaign`: one live campaign, priced turns at 14:00
    and 15:00, an unpriced-model turn at 14:30 inside its window and another outside any
    window; assert the campaign's `conductor_usd` equals the priced inside-window turns only,
    `idle_usd` equals the priced outside-window turns only, `totals.unpriced_turns == 2`, and
    `attribute()` returns the same share.
  - `test_export_conductor_usd_with_unpriced_turn_in_window`
    (`tests/test_agentic_campaign_export.py`): the same shape through `export_tables`; the
    column equals the priced sum and `cost_with_conductor_usd` adds it to `cost_usd`.
  - `test_conductor_session_reader_option_through_cli`: `conductor-session add --reader x`
    then `list --reader x` and `list` (default): the first shows the session, the default
    shows none.
  - `test_conductor_session_list_json_marks_missing_transcript` and
    `test_conductor_cost_text_without_session_or_transcript`: with an empty registry the
    text output has `no conductor session registered`; with a registered session and no
    transcript it has `no transcript for session <id>`.
  - `test_conductor_cost_text_shows_partial_suffix`: CLI text run over the mixed fixture
    contains `(partial: 1 unpriced turns)` and `no price for: other-y`.
- **Fault injection** (run once by hand, recorded in As shipped): revert the `live_end` use
  in `_live_at` and `test_terminal_state_without_transition_stops_absorbing` fails; remove
  the `try` in `export_tables` and `test_export_survives_attribute_raising` fails; restore `read_text` in
  `read_turns` and `test_read_turns_streams` fails.
- **Manual verification:** run `wt queue conductor-cost --json` before and after the change
  against the real registry and transcript; `totals`, `by_day` and `context` are identical
  (the change affects memory, not results). Time `/usr/bin/time -v` peak RSS of

  tools/spec_lint.py` and confirm the amended SPEC-0299 still lints.
- **Regression guard:** full `uv run pytest`; `tests/test_agentic_followers.py` and the
