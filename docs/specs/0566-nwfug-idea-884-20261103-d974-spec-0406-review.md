## Context

[SPEC-0406](./0406-shared-campaign-history-data-layer-nw-campaign.md) shipped the shared
history data layer (`src/nightwright/agentic/history.py`) and the `nw campaign history` /
`records` CLIs (`src/nightwright/agentic/cli_campaign.py`). Its review left three minor
findings, filed as IDEA-1014 (from IDEA-884):

1. **`nwfu:005c49a99247` (test_reviewer/AC1).** `test_history_clis_do_not_write` in
   `tests/test_cli_campaign_history.py` hashes only the files under the fixture data directory
   (`invoke.root`, which is `tmp_path / "fixture"`). A CLI that wrote anything elsewhere under
   `tmp_path` (a sibling file, a new directory, an empty directory) would pass. The direct-function
   test `test_history_fixture_reads_are_pure_and_import_is_ui_independent` in
   `tests/test_history_fixture.py` already checks the top level of `tmp_path`, but only by
   entry name, not by content or nesting.
2. **`nwfu:53fff2c6e2f7` (adversarial_reviewer/path_traversal).** `H._campaign_history` does
   `store.campaign_dir(cfg, cid)`, which is `campaigns_dir(cfg) / cid`. An absolute `cid` replaces
   the root, and `..` components escape it, so `nw campaign history /some/dir` (or
   `../../x`) derives a document from any directory holding a `state.json`. The cached path is
   already guarded (`history_cache.campaign_history` calls `store._contained_campaign_dir`,
   `history_cache.py:3210`), but `H.campaign_history` takes the uncached branch whenever the cache
   is disabled (the default), and the CLI's own `store.campaign_dir(cfg, campaign).is_dir()` probe
   (`cli_campaign.py:508`) joins the raw id too. `store._contained_campaign_dir` (SPEC-0431)
   already encodes the right rule: a single name, no separators, no `.`/`..`, and a symlink that
   resolves outside the root is not a campaign.
3. **`nwfu:7608a60f7f86` (adversarial_reviewer/logic).** A decision row whose escalation is derived
   from text gets `linked_by = "text"` (`_single_escalation`). The final pass in
   `_global_records` (`history.py:946-949`) then calls `_campaign_text_link`, which returns
   `"field"` whenever the record's `campaign` is explicit, and assigns that unconditionally. The
   record then claims `field` provenance although one of its links was inferred from text. The
   same unconditional assignment exists for decisions in the cache's incremental reader
   (`history_cache.py:2386-2388`). `_enrich_records` already merges with
   `max(..., key=_LINK_RANK)`; the final pass should do the same.

## Goals / Non-goals

**Goals**
- The CLI purity test detects any file or directory created, changed or removed anywhere under
  `tmp_path`, not only inside the data directory.
- A campaign id that is not a single name directly under the campaigns root is rejected by
  `H.campaign_history` (cache on or off) and by the history CLI before any filesystem read of the
  joined path, and reads nothing outside the campaigns directory.
- `linked_by` on a record is the weakest-provenance (highest `_LINK_RANK`) of all the links the
  record carries, in both the full derivation and the cache's incremental decision reader.

**Non-goals**
- No change to the record or history schemas, to `_LINK_RANK` ordering, or to cache layout.
- No change to `store.campaign_dir` itself (it is used by writers across the codebase); the guard
  lives at the history read boundary.
- No change to how `records --campaign` filters (it compares strings, it does not join a path).

## Decision

Apply three independent, small fixes to the existing SPEC-0406 surfaces: (1) make the CLI purity
test snapshot the whole `tmp_path` tree, files and directories; (2) gate every history entry point
that joins a caller-supplied campaign id on `store._contained_campaign_dir`, and report a rejected
id as the same `campaign <id> not found` outcome an unknown id already gets; (3) merge `linked_by`
in the final campaign-link pass with `max(..., key=_LINK_RANK)` instead of overwriting it.

## Design

**Purity test (finding 1).** The `invoke` fixture in `tests/test_cli_campaign_history.py` gains
`run.tmp = tmp_path`. `test_history_clis_do_not_write` replaces its local `hashes()` with a snapshot
of `invoke.tmp.rglob("*")` that records every entry: `(relative posix path, "dir")` for directories
and `(relative posix path, sha256)` for files. The assertion compares the snapshot before and after
the three CLI calls, so an extra file, an extra empty directory or a changed file anywhere under
`tmp_path` fails. The existing direct-function test in `tests/test_history_fixture.py` swaps its
`{path.name for path in tmp_path.iterdir()} == {"history-data"}` check for the same whole-tree
snapshot of `tmp_path` (reusing the file's `tree_hashes` idea, extended with directories).

**Campaign-id confinement (finding 2).**
- `H._campaign_history` (the single place `history.py` joins the id) first calls
  `store._contained_campaign_dir(cfg, cid)`; when it returns `None` it raises
  `ValueError(f"campaign {cid} not found")`, exactly like the existing missing-directory error, and
  uses the returned path as `root`.
- `H.campaign_history` and `history_cache.campaign_history` keep their behavior; the cached path
  already raises the same `ValueError`. Because the uncached path now also guards, the result no
  longer depends on whether the cache is enabled.
- `cli_campaign.py` history command: in the `except ValueError` handler (`:507-510`) the
  `store.campaign_dir(cfg, campaign).is_dir()` probe is replaced by
  `store._contained_campaign_dir(cfg, campaign) is None or not <that path>.is_dir()`, so a
  traversal id is never joined and probed; it raises `click.ClickException("campaign <id> not
  found")`. The positional-dispatch probe in the `note` command (`:673`) is switched to the same
  helper so an absolute first argument cannot be probed either.
- The helper stays private to `store`; callers use it as `history_cache.py` already does.

**Provenance merge (finding 3).** In `_global_records` (`history.py:946-949`) and the decisions
reader in `history_cache.py` (`:2386-2388`), replace

```python
kind = _campaign_text_link(rec, campaigns)
if kind:
    rec["linked_by"] = kind
```

with a merge that keeps the weaker provenance:

```python
kind = _campaign_text_link(rec, campaigns)
if kind:
    rec["linked_by"] = max((rec["linked_by"], kind), key=lambda k: _LINK_RANK[k])
```

A decision with an explicit `campaign` and a text-derived escalation therefore stays `text`; a
decision whose campaign is text-inferred stays `text`; a record with only field links stays
`field`. `_enrich_records` is unchanged.

## Alternatives considered

- **Harden `store.campaign_dir` itself** — it is a hot path used by writers and by trusted
  internal ids; changing its contract risks unrelated behavior. The guard at the history read
  boundary reuses the existing SPEC-0431 helper instead.
- **Validate ids with a regex in the CLI only** — would leave the library entry point
  `H.campaign_history` (used by the TUI and cache) unguarded when the cache is off.
- **Snapshot only the CLI test's `tmp_path` file contents** — misses created empty directories,
  which the whole-tree snapshot with directory entries catches.

### As shipped (2026-11-12)

- `H._campaign_history` guards with `store._contained_campaign_dir`; the CLI uses a small
  `_campaign_dir_exists` helper in `cli_campaign.py` for the history error probe and the `note`
  positional probe. Provenance merged with `max(..., key=_LINK_RANK)` in `_global_records` and the
  cache's decision reader. The cache schema version is not bumped: run
  `nw campaign history --rebuild-cache` to refresh any cached text-escalation decision that carries `field`.

## Rollout / migration

No data migration. Cache entries are derived and disposable; if a cached record carries a stale
`field` value for a text-escalation decision, `nw campaign history --rebuild-cache` regenerates it
(note this in the spec's *As shipped* section if the cache schema version is not bumped).
