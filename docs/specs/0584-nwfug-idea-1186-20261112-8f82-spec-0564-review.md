## Context

[SPEC-0564](./0564-spec-0476-follow-up-runs-pane-test-strength-gaps.md) is `done`: it
strengthened `tests/test_tui_campaign_runs.py` (one module-level `pytestmark = pytest.mark.tui`)
for the Runs pane of the Campaign detail screen. Its review (campaign
`IDEA-1186-20261112-8f82`) left seven minor findings, filed as IDEA-1327. They are all
about test honesty, one missing case, and what the gate actually ran; none is a product bug.
SPEC-0564 is past `draft`, so it is not edited; this spec is the follow-up.

State on the current branch (checked before writing this spec): the empty-string lead
assertion that two findings name is already gone from `test_verdict_line_lead_fallbacks`,
and SPEC-0564 already has an *As shipped* section with the mutation table. Those findings
describe the reviewed diff, not the current tree, so for them this spec adds a check that
they stay true rather than new work. Two items are real:

| Finding | Where | Disposition |
|---|---|---|
| `f26243c0f45b` 3a is not independent of worker cancellation | `test_stale_run_detail_dropped_on_switch` | Real: the test claims more than it proves. Design 1. |
| `e3cb6abd1465`, `3eba991efa67`, `f66fd01e727e` empty-string lead pinned | `test_verdict_line_lead_fallbacks` | Already removed; keep it removed. Design 2. |
| `c236f907da97` no-verdict fallback to the first body line untested | `test_verdict_line_lead_fallbacks` | Real: new test. Design 3. |

Why finding 1 is true: `_load_run_detail_async` (`src/nightwright/tui/campaign_detail.py:837`)
awaits `asyncio.to_thread(AM.load_run_pane_detail, ...)`, and the Runs detail worker is
`exclusive`. When run B is selected, the worker for run A is cancelled at that await
(`CancelledError`), so A's late snapshot normally never reaches the token check
(`campaign_detail.py:851`) or the `_selected_run_id` check (`:853`). The test therefore pins
the end state of the switch (worker cancellation and the guards together), not that either
guard is needed. SPEC-0564 Design 3a says "Both guards trip here"; that sentence is wrong
for the normal path, and the guard-independence proof is 3b and 3c, which await
`_load_run_detail_async` directly.

## Goals / Non-goals

**Goals**

- Make `test_stale_run_detail_dropped_on_switch` say exactly what it proves and point at the
  tests that prove guard independence.
- Keep the empty-string lead out of the tests.
- Cover the "no verdict line, no blocking row, empty stderr: first line is the first body
  line" step of the lead-fallback chain.
- Run the `tui`-tier tests of this module explicitly (the affected-tests gate deselects
  them) and record the result.
- Confirm SPEC-0564's recorded mutation check, and mutation-check the one new test.

**Non-goals**

- Any product change, new module, or new speed-tier marker.
- Editing SPEC-0564 (it stays a faithful `done` record).
- Changing the gate's `-m` expression (SPEC-0490); the tui tier is meant to be deselected
  from the fast gates and is run by the cadence jobs and by hand.

## Decision

Make three small edits to `tests/test_tui_campaign_runs.py` (a docstring, a removal check,
one new test), run the module explicitly with `-m tui`, and record the run and the new
mutation in this spec's *As shipped*. No production code changes.

## Design

### 1. 3a states what it proves (`f26243c0f45b`)

Give `test_stale_run_detail_dropped_on_switch` a docstring: it pins the end state after a
slow load for run A finishes while run B is selected (stored run id, renderer, offset,
head, body, no repaint); A's worker is normally cancelled at the thread await, so the test
does not show that the token check or the selection check is needed; that is
`test_late_load_token_guard` and `test_late_load_selection_guard`. The assertions stay
as they are. No other behavior changes. This spec's text is the correction of SPEC-0564
Design 3a.

### 2. No empty-lead pin (`e3cb6abd1465`, `3eba991efa67`, `f66fd01e727e`)

`test_verdict_line_lead_fallbacks` has no case with a `""` lead key and no assertion that
`verdict_status` is `""` or that the first line starts with a space. If one is found on the
branch at implementation time, remove it; the spec never asked for it (SPEC-0564 Design 2
tests `null` leads and absent leads only). Whether an empty-string lead should fall through
is a product question and is not decided here.

### 3. First-body-line fallback (`c236f907da97`)

The first line of `RunPaneDetail.text` (`agentic_model.py`, `load_run_pane_detail`) is the
verdict line, else the first blocking row, else the first stderr line, else the first body
line. The last step is reachable only when `stderr.log` exists and is empty:
`_stderr_tail_text` then appends nothing, whereas a missing `stderr.log` appends
`no stderr`. Add `test_detail_first_line_falls_back_to_body` in the same module, on copies
made with `_copy_campaign` / `_stream_copy`:

- Stream run: copy the stream campaign, write an empty `stderr.log`, set `run.json`
  `verdict` to `{}` (no verdict line, no blocking rows) and `stream.jsonl` to the
  `_tool_result_event` events `tool-out-0000..0002`. Assert
  `snap.head.plain == ""`, `snap.text.plain.splitlines()[0] == _tool_out(0)` and
  `== snap.body[0]`.
- Result fallback run (no `stream.jsonl`): the copied multi-run campaign run with an empty
  `stderr.log` and `verdict {}`. Assert `snap.head.plain == ""` and the first line of
  `snap.text.plain` equals `snap.body[0]` (the first line of the pre-stream result), which
  is non-empty.
- Ordering against the earlier steps, one assertion each: with a verdict `{"blockers":
  ["blk-0584"]}` the first line is `major: blk-0584` (a blocking row beats the body); with a
  one-line `stderr.log` the first line is that stderr line (stderr beats the body); with
  no `stderr.log` the first line is `no stderr`.

The test calls `AM.load_run_pane_detail` directly; no pilot, no sleep.

### 4. The tui tier is executed (`ff1e9ee103df`)

The pytest-affected gate runs with `-m "not (integration or tui or remote or perf) or
tree_guard"` (SPEC-0490), so `tests/test_tui_campaign_runs.py` (marked `tui`) is deselected
and the gate's pass count says nothing about it. The implementer therefore runs
`uv run pytest -q -n 3 -m tui tests/test_tui_campaign_runs.py` (a command-line `-m`
overrides the gate's), and
`uv run pytest -q --collect-only -m tui tests/test_tui_campaign_runs.py` to show the
module collects a non-zero number of tests, and records the pass counts in *As shipped*.
`-n 3` load made `test_poll_does_not_cancel_slow_stream_tail` flaky in SPEC-0564's run;
if that test fails under `-n 3`, re-run it alone and record both results rather than
treating it as caused by this change.

### 5. Mutation check is recorded (`c6ed65015b06`)

SPEC-0564 has a *As shipped (2026-11-12)* section with a twelve-row mutation table. This
spec verifies that section is still present (AC5) and records, in its own *As shipped*, the
mutation for the new test: temporarily make `RunPaneDetail.text` omit the body (or insert a
placeholder first line when `stderr.log` is empty) in a scratch copy, and show
`test_detail_first_line_falls_back_to_body` fails; revert.

## Alternatives considered

- **Delete `test_stale_run_detail_dropped_on_switch`.** It still guards the end state of a
  real user flow (select slow run, switch away) and costs one test; only the claim was wrong.
- **Make 3a reach the guards by un-cancelling the worker.** That would test a path the
  product does not take; 3b and 3c already prove each guard with direct awaits.
- **Edit SPEC-0564 to add the missing text.** It is `done`; the contract forbids rewriting it.
- **Add the tui tier to the gate.** It is deliberately slow and excluded by SPEC-0490;
  running it explicitly for this change is cheaper than changing the tiering.

## Test plan

- **Automated tests:** all in the existing `tests/test_tui_campaign_runs.py`, tier `tui`
  (`pytestmark = pytest.mark.tui` already present; no second marker, no new module). New:
  `test_detail_first_line_falls_back_to_body` (AC3). Edited: docstring of
  `test_stale_run_detail_dropped_on_switch` (AC1); `test_verdict_line_lead_fallbacks`

- **Tier execution (AC4):** `uv run pytest -q -n 3 -m tui tests/test_tui_campaign_runs.py`

- **Regression guard:** the rest of the module stays green;
