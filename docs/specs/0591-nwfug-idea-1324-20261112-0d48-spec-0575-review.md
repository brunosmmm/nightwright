## Goals / Non-goals

**Goals**
- Every one of the five tests fails when the behaviour it is meant to guard is removed.
- Each such claim is shown once with a recorded mutation check (finding 2 needs none).

**Non-goals**
- No change to `src/`. If a stronger assertion shows a real product defect, the implementer
  records it in *As shipped* and files a separate idea; this spec stays a test-strength change.
- No new test module, no new fixture file, no new speed tier.
- No change to the equality tests for add, remove and add+remove.

## Decision

Strengthen the five existing tests in place, each by the smallest assertion that is false when
the guarded behaviour is removed, and prove each strengthened test with a scratch mutation of
`history_cache.py` that is reverted afterwards. Only `tests/test_history_cache.py` changes.

## Design

All edits are inside `tests/test_history_cache.py`, which already carries
`pytestmark = pytest.mark.fast`.

1. **Gaps guard (finding 1).** In `test_reconcile_one_global_resolve_and_snapshot`, after the
   warm `H.history_index(...)` and before `_install_terminal_campaign`, append one complete
   unparsable line (`"not json\n"`) to `data_dir/agentic/mailbox/human.jsonl`. The mail
   `_add_mail` already wrote is what makes `_A` differ, so step 5 recomputes `_A`, and
   `_global_records` now reports `mailbox/human.jsonl: line N unparsable`. Assert that
   `H.campaign_history(c, _A, now=NOW, cache=False)["gaps"]` contains an `unparsable` entry
   (so the equality is no longer `[] == []`), that the stored `_A` document's `gaps` contains
   the same entry, and keep the equality. The stored `_A` document cannot already hold the gap,
   because it was written before the line was appended.
2. **Grep location (finding 2).** In `test_no_drop_campaign_all_in_src`, compute
   `src_root = Path(__file__).resolve().parents[1] / "src" / "nightwright"`, assert
   `src_root.is_dir()` and `(src_root / "agentic" / "history_cache.py").is_file()` directly,
   remove the `or` guard and the dependence on `HC.__file__`, then keep the `rglob("*.py")`
   scan for `drop_campaign_all`.
3. **One-snapshot guard (finding 3).** In
   `test_reconcile_directory_added_mid_call_picked_up_next_call` the `late` directory is
   created inside the first `_recompute_campaign` call, which is the step-4 recompute of `_N`.
   That is before step 5, so a step 5 that re-lists the live set sees `late`. Add: a spy on
   `H._global_records` records its `cids` argument, and the test asserts it was called once,
   with a list that does not contain `late` and does contain `_A` and `_N`. Also assert that
   no stored `_A`, `_N` document and no global record returned by the first call has
   `campaign == late`, and that the first call's returned records equal the stored documents'
   global records for `_A` (no half-applied state). The existing next-call assertions stay.
4. **Exact recompute set (finding 4).** In `test_each_id_recomputed_once_per_live_set_change`
   replace the interval assertion with `set(counts) == expected`, where `expected` is derived
   from the fixture and not from `counts`: `differing | {_N} | mailbox_owners`, with
   `mailbox_owners` the campaigns that own a record of `source == "mailbox"` in
   `before_records` (the only global source the test changes). If the run shows the product
   recomputes a different set, the implementer replaces the derivation with the observed set
   written as an explicit literal built from the fixture's ids, and records the reason in
   *As shipped*. Never an interval. `set(counts.values()) == {1}` stays.
5. **`persist=False` new-id document (finding 5).** In
   `test_reconcile_persist_contract_recompute_path`, for `persist=False` also assert: the file
   `campaigns/<_N>.json` exists, parses, and has `campaign == _N`; `out[0]` contains an index
   row for `_N` and no stored index row changed on disk; `out[1]` contains a local-source
   record for `_N`; and `_N` is a key of `out[2]["campaign_files"]` while the on-disk
   `sources.json` bytes are unchanged. The `persist=True` branch is untouched.

## Alternatives considered

- **Change `src/` to make the old assertions trivially true** — the findings are about test
  strength, not behaviour; a source change would need its own spec.
- **Add new tests beside the weak ones** — leaves the weak tests in place and under-claiming;
  strengthening in place keeps one test per acceptance criterion.
- **Delete the grep test** — SPEC-0567's Test plan promised it; fixing the lookup is cheaper.
