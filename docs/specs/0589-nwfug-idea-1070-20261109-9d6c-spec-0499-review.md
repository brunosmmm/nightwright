## Context

[SPEC-0499](./0499-tests-fire-real-desktop-notifications-only-tests.md) stops the suite from
launching the session's real `notify-send`: the autouse fixture `_no_desktop_notify` in
`tests/conftest.py` stubs `escalations._run_notify` and installs a fail-closed guard over
`subprocess.run` and `subprocess.Popen`. Its review left five minor findings, all in the guard
or in its tests (`tests/conftest.py:113-150`, `tests/test_no_desktop_notify.py`):

1. **Bare-name argv untested** (`nwfu:39b1035d7bb6`, `nwfu:f7eabca23c7f`).
   `test_subprocess_notify_send_fails_closed` only passes the absolute path of the fake script as a
   list, and a shell string. `subprocess.run(["notify-send", ...])` and
   `subprocess.Popen(["notify-send", ...])`, the argv the production code builds, are never
   exercised.
2. **Argv forms the classifier misses** (`nwfu:3ab68e195142`, `nwfu:e339ffd18eee`).
   `_is_notify_send` classifies a list or tuple by `os.path.basename(str(argv[0]))`, and a `str` by
   its first whitespace token. Not caught, and still exec `notify-send`: a `bytes` command
   (`str(b"/usr/bin/notify-send")` is `"b'/usr/bin/notify-send'"`), a bare `os.PathLike`, a list
   whose first element is `bytes` or a `PathLike`, and a shell command that reaches the binary
   past its first word (`sh -c "notify-send t b"`, `env X=1 notify-send t b`,
   `true && notify-send t b`).
3. **Guard skipped by import-time bindings** (`nwfu:382665992991`). The fixture rebinds the module
   attribute `subprocess.Popen` to a subclass. Anything that took the real class before the fixture
   ran keeps it: `gates._MeteredPopen(subprocess.Popen)` (`src/nightwright/agentic/gates.py:378`,
   built at import, used at `gates.py:538`) and the `popen=subprocess.Popen` default arguments in
   `queue.py:8520` (`detach_runner`), `restart.py:293` and `herdr_autowatch.py:187`. Pytest imports
   those modules at collection, before any fixture, so a test that reaches `notify-send` through
   them is not blocked.

## Goals / Non-goals

**Goals**
- Guard every `subprocess`-level spawn path, including a `Popen` subclass or default argument
  bound at import, with one interception point that needs no source change under `src/`.
- Classify `bytes`, `PathLike`, mixed-type list argv, and shell command lines (a `sh -c` script, or
  a shell string with a later command word) as `notify-send` when they exec it.
- Prove all of it with tests, including the bare-name argv, and prove that unrelated commands
  that merely mention `notify-send` are not blocked.

**Non-goals**
- No change to `src/nightwright/`. Under the chosen design the modules named by finding 3 stay as
  they are.
- No guard over spawns outside `subprocess` (`os.system`, `os.exec*`, `os.posix_spawn`). Nothing
  in the suite uses them for `notify-send`; a later spec can add them if one does.
- No change to the `_run_notify` stub, to `notify=auto` behavior, or to which tests opt out of the
  guard (none do).
- No attempt to parse arbitrary shell. The shell classifier is a deliberately small,
  conservative command-position scan, not a shell interpreter.

## Decision

Guard `subprocess.Popen.__init__` in place instead of rebinding `subprocess.Popen`, and replace
`_is_notify_send` with a normalizing classifier. Every spawn in `subprocess` (`run`, `call`,
`check_output`, `Popen(...)`, `asyncio` subprocesses) constructs a `Popen`, and every subclass
and every import-time alias of `subprocess.Popen` is the same class object (or inherits its
`__init__`), so one patch covers all of them, closing finding 3 without touching `src/`. The
classifier decodes every argv form to text before comparing, and looks past a shell wrapper to
the command it runs, closing finding 2. The bare-name argv tests close finding 1.

## Design

All guard code stays in `tests/conftest.py`, inside or next to `_no_desktop_notify`.

**Interception point.** Delete the `subprocess.run` wrapper and the `_GuardedPopen` subclass.
Install, with `monkeypatch.setattr(subprocess.Popen, "__init__", _guarded_init)`:

```python
_real_init = subprocess.Popen.__init__

def _guarded_init(self, args, *a, **kw):
    if _is_notify_send(args):
        raise AssertionError(f"notify-send blocked in tests: {args!r}")
    _real_init(self, args, *a, **kw)
```

`Popen._child_created` is a class attribute (`False`, `subprocess.py`, "Set here since `__del__`
checks it", verified on Python 3.14.7), so the half-built object that `raise` leaves behind has
`Popen.__del__` return at once; `_guarded_init` must therefore not set any instance state before
raising (setting `_child_created = True` there, or touching other attributes, would make `__del__`
poll a process that never started). The unraisable-`__del__` test below guards that.

`subprocess.run` and the other helpers call `Popen(...)` through the module global, so they reach
`__init__` without a second wrapper. A subclass such as `gates._MeteredPopen` (it defines no
`__init__`) and a reference captured at import (`popen=subprocess.Popen` defaults) resolve to this
same class attribute at call time. `monkeypatch` restores the original `__init__` at teardown.
`subprocess.Popen` itself is no longer replaced, so `isinstance(proc, subprocess.Popen)` and
`class X(subprocess.Popen)` keep their ordinary meaning.

**Classifier.** `_is_notify_send(cmd) -> bool`, with a depth limit of 3 for nested shells:

1. *Normalize to words.* `bytes`/`bytearray` decode with `os.fsdecode`; an `os.PathLike` goes
   through `os.fspath` then `os.fsdecode`; a `list`/`tuple` is normalized per element the same way
   (anything else through `str`); a `str` is the shell command line (it is classified whether or not
   `shell=True`, as today, to stay conservative). A single `bytes`/`PathLike` command is a
   one-word argv.
2. *Program match.* `os.path.basename(words[0]) == "notify-send"` is a hit.
3. *Shell wrapper.* If the basename of `words[0]` is `sh`, `bash`, `dash`, `zsh` or `ksh` and a
   later word is `-c` or a bundled flag containing `c` (`-lc`, `-ec`), classify the word after it
   as a shell command line (step 4).
4. *Shell command line.* Tokenize with
   `lex = shlex.shlex(line, posix=True, punctuation_chars=";&|()\n<>")`,
   `lex.whitespace_split = True`, `lex.whitespace = " \t\r"`. Each setting matters (checked
   against Python 3.14.7): `whitespace_split = True` stops a word that holds a character outside
   `wordchars` (`+`, `@`, `:`, `%`, `,`) from being cut into several tokens, so
   `/opt/foo+1/notify-send` and `X=a:b` stay one word each; taking `\n` out of `whitespace` and
   putting it in `punctuation_chars` makes a newline run its own token (with the default
   whitespace the newline vanishes and `echo hi\nnotify-send t` reads as one `echo` command, and
   with `\n` in neither set it glues to the next word as `hi\nnotify-send`). A token made only of
   characters from `;&|()\n` (`;`, `&&`, `||`, `|`, `(`, `)`, `\n\n`) is a *separator*; a
   redirection token such as `>` or `2>&1`'s `>&` is an ordinary word. If `shlex` raises
   `ValueError` (unbalanced quote, e.g. `true&&notify-send "x`), fall back to
   `re.sub(r"([;&|()\n])", r" \1 ", line).split()`, which puts a space around each separator
   character and then whitespace-splits, so the unquoted separators still split. For each simple
   command (the words between separators): skip
   leading `NAME=value` words and the wrapper words `env`, `exec`, `command`, `nohup`, `nice`,
   `setsid`, `sudo`, `time`, `timeout`, `stdbuf`, together with any following word that starts
   with `-` or is all digits; the next word is the command word. A command word whose basename is
   `notify-send` is a hit; a shell command word is handled as in step 3 (recursion).
5. A `notify-send` word anywhere else (an argument of `echo`, `git commit -m`, `which`,
   `shutil.which`, `grep`) is not a hit.

The message keeps the text `notify-send blocked in tests`, which the existing tests match on.

**Tests** extend `tests/test_no_desktop_notify.py` (its module-level `pytestmark = pytest.mark.fast`
already exists; no second tier is added). A module-level `_IMPORT_TIME_POPEN = subprocess.Popen`
and a module-level `class _SubPopen(subprocess.Popen)` give import-time bindings for the finding 3
tests. Imports from `nightwright.agentic` for the real subclass (`gates._MeteredPopen`) and the real
default-argument holders (`queue.detach_runner`, `restart`, `herdr_autowatch`) are done inside the
test functions.

## Alternatives considered

- **Patch `Popen` in every module that bound it** (`gates`, `queue`, `restart`, `herdr_autowatch`),
  as the finding's file list suggests: new import sites would silently escape again, and the
  test fixture would need to know the production import graph. One class-level patch needs none.
- **Make the production modules look `subprocess.Popen` up at call time** (change `popen=` defaults
  to `None`, or have `_MeteredPopen` resolve its base late): a source change to satisfy a test
  fixture, and it still would not cover a future subclass.
- **Wrap `subprocess.Popen` in a PATH-level shim** (put a failing `notify-send` first on `PATH`):
  does not stop an absolute-path call, and a "fake that runs" is what SPEC-0499 removed.
- **Parse shell with a full parser**: far more code and dependencies than the guard is worth; the
  command-position scan covers the forms that exec the binary in practice.

## Acceptance criteria

- [ ] `tests/conftest.py` no longer rebinds `subprocess.Popen` or `subprocess.run`; it patches
      `subprocess.Popen.__init__` only, and `subprocess.Popen` is the real class object inside a
      test.
- [ ] `subprocess.run(["notify-send", "t", "b"])` and `subprocess.Popen(["notify-send", "t", "b"])`
      raise `AssertionError` matching `notify-send`, with the fake script's marker file absent
      (finding 1).
- [ ] A bare-name tuple argv, and the absolute-path forms, still raise as before.
- [ ] `bytes` argv (`subprocess.run(b"/x/notify-send")`), a bare `pathlib.Path(".../notify-send")`,
      a list whose first element is `bytes` (`[b"/x/notify-send", b"t"]`) and one whose first
      element is a `Path` all raise `AssertionError`, and the marker stays absent (finding 2).
- [ ] `sh -c "notify-send t b"` (as a list, and as the string with `shell=True`),
      `bash -lc 'notify-send t'`, `env X=1 notify-send t b`, `true && notify-send t b`,
      `timeout 5 notify-send t b`, and a nested `sh -c "sh -c 'notify-send t'"` all raise
      `AssertionError`, and the marker stays absent (finding 2). So do the forms that only a
      correct tokenizer sees: the unspaced separators `"true;notify-send t"` and
      `"true&&notify-send t"`, a newline separator `"echo hi\nnotify-send t"`, a path with a
      non-word character `"/tmp/a+b/notify-send t"`, an assignment value with a colon
      `"X=a:b notify-send t"`, and an unbalanced-quote line `'true&&notify-send "x'` (the
      `ValueError` fallback).
- [ ] A class defined at import (`_SubPopen(subprocess.Popen)`), a module-level alias of the real
      `subprocess.Popen` taken before the fixture ran, and the real `gates._MeteredPopen`, each
      raise `AssertionError` when constructed with a `notify-send` argv, and the marker stays
      absent (finding 3).
- [ ] The default `popen` of `queue.detach_runner` (`queue.py:8520`), `restart.apply_restart`
      (`restart.py:293`) and `herdr_autowatch.Supervisor.__init__` (`herdr_autowatch.py:187`), called
      with a `notify-send` argv, fails closed (finding 3). The test finds each default by
      `inspect.signature`, so it follows the code if the line moves.
- [ ] Commands that only mention `notify-send` run normally: `["echo", "notify-send"]`,
      `["git", "--version", "notify-send"]` (extra argument, nonzero exit allowed),
      `"echo notify-send"` with `shell=True`, and
      `["which", "notify-send"]` exit without `AssertionError`.
- [ ] A blocked `Popen` construction raises no unraisable exception when the half-built object is
      collected: with `sys.unraisablehook` replaced by a recording function, the blocked
      construction, `del` of the caught exception and `gc.collect()` leave the record empty.
      `_guarded_init` sets no instance state before raising.
- [ ] The existing tests in `tests/test_no_desktop_notify.py` pass unchanged:
      `test_other_subprocess_commands_still_run` and `test_popen_of_other_commands_stays_a_popen`
      (a `Popen` of an unrelated command still returns a real `Popen`, `communicate()` works).
- [ ] `src/nightwright/` has no diff (the modules named in finding 3 are untouched).

## Test plan

- **Automated tests** (all in `tests/test_no_desktop_notify.py`, which already carries its one
  module-level marker `pytestmark = pytest.mark.fast`; no new test module, no second tier). All
  use the `fake_notify_send` fixture and assert its `marker` file never appears:
  - `test_subprocess_notify_send_bare_name_fails_closed`: parametrized over `subprocess.run` and
    `subprocess.Popen`, list and tuple argv with the bare `notify-send`.
  - `test_notify_send_non_str_argv_fails_closed`: `bytes`, `bytearray`, `Path`, `[bytes, ...]`,
    `[Path, ...]`.
  - `test_notify_send_behind_a_shell_fails_closed`: the `sh -c`, `bash -lc`, `env`, `&&`, `timeout`
    and nested forms in the Acceptance criteria, both as list and string/`shell=True` where
    applicable, plus the tokenizer cases `"true;notify-send t"`, `"true&&notify-send t"`,
    `"echo hi\nnotify-send t"`, `"/tmp/a+b/notify-send t"`, `"X=a:b notify-send t"` and
    `'true&&notify-send "x'` (the `ValueError` fallback).
  - `test_notify_send_mentions_do_not_trip_the_guard`: the non-hit commands.
  - `test_import_time_popen_bindings_fail_closed`: `_IMPORT_TIME_POPEN`, `_SubPopen` and
    `gates._MeteredPopen`.
  - `test_production_popen_defaults_fail_closed`: for `queue.detach_runner`,
    `restart.apply_restart` and `herdr_autowatch.Supervisor.__init__`, read the `popen`
    parameter default with `inspect.signature` and call it with a `notify-send` argv.
  - `test_blocked_popen_leaves_no_unraisable_del_exception`: `monkeypatch.setattr(sys,
    "unraisablehook", seen.append)`; a helper function builds the blocked `subprocess.Popen(["notify-send"])`
    and catches the `AssertionError` (so no frame keeps the half-built object alive); the test
    drops the exception reference, calls `gc.collect()`, and asserts `not seen`. It fails if
    `_guarded_init` is changed to set `_child_created = True` or other state before raising.
  - Existing tests, unchanged, run in the same file.
- **Spec lint / tiers:** `python3 tools/test_tiers.py --check` exits 0 (the module keeps its single
  `fast` marker); `python3 tools/spec_lint.py` exits 0.
- **Manual verification:** with the fake `notify-send` first on `PATH` (as the fixture does), run
  `uv run pytest tests/test_no_desktop_notify.py -q` and confirm the marker file is absent after a
  run. Temporarily revert `conftest.py` to the previous guard and confirm the new tests for
  findings 1 to 3 fail (the bare-name tests may pass; the `bytes`, shell and import-time tests
  must not), then restore.
- **Regression guard:** `python3 tools/affected_tests.py --run uv run pytest -q` (the change is in
  `conftest.py`, so the affected set is the whole suite's autouse surface: the queue's close gate
  runs it). The patched `Popen.__init__` is exercised by every test that spawns a process,
  including `tests/test_gate_timeout_tree.py` (the `_MeteredPopen` path) and the e2e tests. All
  must pass with no new warnings.
