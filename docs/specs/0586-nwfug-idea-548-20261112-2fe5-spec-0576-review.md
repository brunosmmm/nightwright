## Context

[SPEC-0576](./0576-wt-spec-seed-children-an-existing-idea-nnn.md) made `nw spec seed-children`
match a Breakdown bullet worded `existing IDEA-NNN …` to that idea by id across all org
files (`parse_breakdown_existing`, `_EXISTING_IDEA_RE`, and the id lookup / `:AFTER:` stamping in
`seed_ideas_from_epic`, `src/nightwright/specs.py`). Its review (campaign IDEA-548) left five
minor findings, none of which blocked it:

1. **Regex false match.** `_EXISTING_IDEA_RE` starts with `\bexisting`. There is a word
   boundary between `-` and `e`, so `pre-existing IDEA-12` and `non-existing IDEA-12` count as
   the explicit form. If that id exists, the bullet silently maps to it and no child is
   seeded. SPEC-0576's non-goal says only the explicit `existing IDEA-NNN` form may trigger
   a match.
2. **Self-referencing `:AFTER:`.** Two bullets can name the same idea
   (`existing IDEA-7 …` twice, or one `existing IDEA-7` bullet and a second bullet whose heading
   already is IDEA-7's). `idea_of` then holds the same id twice. A `(depends_on child N)` between
   them yields `stamps[IDEA-7] = "IDEA-7"` and the stamping loop writes `:AFTER: IDEA-7` on
   IDEA-7 itself when its `:AFTER:` is blank — a self-dependency. Where several bullets map to
   one idea, the dict comprehension that builds `stamps` also lets a later bullet's prerequisites
   overwrite an earlier one's.
3. **Lowercase id in the bullet is untested end to end.** Only the `parse_breakdown_existing`
   unit test covers `idea-7`. No seeding test proves the `.upper()` normalisation of `ideas_by_id`
   lets `existing idea-450` find `IDEA-450`.
4. **Project annotation plus existing id is untested.** The SPEC-0576 Design says the
   `(project: Name)` annotation on an `existing IDEA-NNN` bullet is still validated (an unknown
   name still hard-fails) but is not applied to the matched idea. No test covers either half.
5. **Docs have no assertion.** SPEC-0576's last acceptance criterion requires the form to be
   documented in `docs/specs/TEMPLATE-epic.md` and the `seed-children` help text; nothing checks
   either.

## Goals / Non-goals

**Goals**
- Only a standalone word `existing` triggers the id match: `pre-existing IDEA-N`,
  `non-existing IDEA-N` and any other hyphen- or word-joined prefix do not.
- No `:AFTER:` stamp ever names the idea it is written on; when several bullets map to the same
  idea, their prerequisite ids are merged, not overwritten.
- Tests cover lowercase ids end to end, the project annotation on an `existing` bullet (both
  halves), and the two doc locations.

**Non-goals**
- Rejecting two bullets that match the same idea: it stays legal (the second is a no-op
  duplicate reference); only the self-dependency is dropped.
- Any other change to SPEC-0576 behavior, the heading-based idempotency, the `(project: …)` /
  `(depends_on …)` syntax, or applying the project annotation to the matched idea.
- Rewording the docs; the existing lines stay, only their presence is asserted.

## Decision

Tighten `_EXISTING_IDEA_RE` with a lookbehind so `existing` must not be preceded by a word
character or a hyphen. Build `:AFTER:` stamps so that an idea's own id is dropped from its
prerequisites and prerequisites from several bullets of the same idea are merged in order,
de-duplicated; an idea whose prerequisite list becomes empty is not stamped. Add the missing
tests to `tests/test_seed_children.py`. A pre-existing mention of the form in prose
(`non-existing IDEA-12`) therefore seeds a new idea like any other bullet.

## Design

- `src/nightwright/specs.py`, `_EXISTING_IDEA_RE`:
  `re.compile(r"(?<![\w-])existing\s+(?:idea\s+)?`?(IDEA-\d+)\b", re.IGNORECASE)`. Start of
  string, whitespace, punctuation, `(` and a backtick before `existing` still match
  (`Fold in existing idea `IDEA-450``). `pre-existing`, `non-existing`, `preexisting` and
  `_existing` no longer match. The comment above the regex and the
  `parse_breakdown_existing` docstring say so. Note `\b…IDEA-\d+\b` at the tail is unchanged.
- `seed_ideas_from_epic`, stamping: replace the `stamps` dict comprehension with a loop over
  `parsed` that, for each bullet `i` with ordinals and a non-empty `idea_of[i]`, builds
  `prereqs = [idea_of[o - 1] for o in ords]`, drops entries equal to `idea_of[i]` or empty,
  and appends them to `stamps[idea_of[i]]` skipping ids already present. A key is created
  only when `prereqs` is non-empty, so an idea whose only prerequisite was itself gets no
  stamp. The later loop that writes `:AFTER:` only when blank, and joins with spaces, is
  unchanged; the stored value is `" ".join(stamps[tid])`.
- The tests and docs checks are listed in the Test plan. No change to `cli.py` or
  `TEMPLATE-epic.md` text; the new test asserts they still contain the documented form.

## Alternatives considered

- **Error when two bullets name the same idea** — rejected: harmless duplicates are common
  while an epic is being edited, and a hard failure adds a new rule beyond the findings.
- **Require whitespace or start-of-string before `existing` (`(?<!\S)`)** — rejected: it would
  stop matching `(existing IDEA-7)` and ``(existing `IDEA-7`)``, which SPEC-0576 accepted.
- **Strip the self id only at the write loop** — rejected: merging per idea in the `stamps`
  build step also fixes the overwrite when several bullets map to one idea.

## Rollout / migration

No data migration. Epics already seeded are unaffected. An epic whose Breakdown relied on
`pre-existing IDEA-N` mapping to the idea would now seed a new idea; reword the bullet to
`existing IDEA-N` (this form was never documented).
