## Context

[SPEC-0300](./0300-quiet-conductor-follower-digest.md) shipped the quiet conductor follower
(`src/wt/agentic/quiet.py`, called from `events.follow`). Its review left ten minor findings,
filed as IDEA-409. This spec fixes the real defects among them and closes the test gaps.

State of the code on `main` when this spec was written:

- **Replay drops held events.** `Digest.add` returns False for any event with `id <=
  max(pending last_id, last_printed_last_id)`. That is the right dedup after a crash between the
  digest write and the cursor write. But a follower that re-reads old events, because the cursor
  file was corrupted (`cursor_get` returns 0), or was deleted and the follower restarted with
  `--from-start`, drops the ones classified `hold`: no digest entry, no `hold` delivery record,
  and the cursor advances past them. (`wtfu:2c9c3d05af46`)
- **What triggers a replay today.** `--from-start` applies only to a reader with no cursor file;
  an existing cursor is resumed (`events.follow` uses `from_start` only to skip the
  brand-new-reader `cursor_set` to the end of the stream). A deleted cursor file without
  `--from-start` takes the brand-new-reader path and starts at the end of the stream, re-reading
  nothing. Only an invalid-JSON or non-int `after` cursor file gives `cursor_get == 0` by itself.
  This spec leaves all of that unchanged.
- **Corrupt digest file.** The reviewed text crashed the follower on a wrong-typed field.
  `_well_typed` / `_FIELD_OK` now treat a wrong-typed file as absent, and
  `test_corrupt_digest_file_falls_back_to_fresh` covers nine records. The check is shallow: it
  tests the container type, not the elements, so `{"held": {"merged": "x"}}` still raises in
  `Digest.add` (`p["held"].get(t, 0) + 1`). (`wtfu:0536b0706d05`)
- **File name collision.** The cursor is `cursors/<safe(reader)>.json` and the digest is
  `cursors/<safe(reader)>.digest.json`; `_safe` keeps dots. A reader named `conductor.digest`
  uses the conductor's digest file as its cursor, and `E.followers` hides any reader whose name
  ends in `.digest`. (`wtfu:72f638de3a3b`, `wtfu:d3150cb45997`, the same defect found twice)
- **Unbounded silent/stuck hold.** `_silent_hold` holds `campaign_silent` and `state_stuck`
  whenever the campaign is in `lease.in_flight`, which covers every pool flight. The watchdog
  fires each of these once per `type:campaign:state` key, so a gate or close that hangs inside
  the pool is held once and never reaches the conductor again; it shows up only as a count in a
  digest. (`wtfu:133bd8d1c176`)
- **Test gaps** in `tests/test_agentic_quiet.py`: delivery record fields, a digest line counting
  toward `max_events`, the `Ctx.lease` -> `L.lease_status` path, the less common ping
  fingerprint categories and digest caps, and the window and `--until` bounds of
  `wakeups_report`. (`wtfu:64cab66d61c7`, `wtfu:a005b75d5cfe`, `wtfu:e27244c668a8`,
  `wtfu:b1922ab37baf`, `wtfu:d6a60b1b24d4`)

The 12 further findings of the SPEC-0300 review (capped, then waived or deferred by the triager)
stay out of scope; see Non-goals.

## Goals / Non-goals

**Goals**
- A replayed follower (cursor 0: `--from-start` with no cursor file, or a corrupt cursor file)
  never drops a held event.
- A damaged digest file of any shape is ignored, never a crash, at the element level too.
- A reader's digest file can never be a reader's cursor file, whatever the reader is named.
- A held `campaign_silent` or `state_stuck` for a campaign that stays in flight wakes the
  conductor once, after a bound, with its age refreshed.
- Each test gap above has a test that fails if the behavior breaks.

**Non-goals**
- Rotating or compacting `deliveries.jsonl` (waived in the SPEC-0300 review).
- Binding a held `runner_draining` to the exact drain it described (`track_drain`).
- Making `--campaign` work with `--follow`; the `ping_items=n` text suffix test; any other
  finding the SPEC-0300 triager waived.
- Changing which event types hold or wake (`RULES`), or what `events.sync` appends.

## Decision

1. **Replay resets the seen-state.** When a quiet follower starts and the reader's cursor is 0
   (no cursor file with `--from-start`, or a corrupt cursor file), it starts from a fresh
   digest: pending fields, `last_printed_last_id`, `last_ping_fp`, `drains` and the new
   `watches` are all reset and saved. Every re-read hold is then folded in. The crash-recovery
   dedup stays for a non-zero cursor.
2. **Deep digest validation.** `_FIELD_OK` checks element types of `held`, `campaigns`,
   `merged`, `ping_items`, `last_ping_fp` and `watches`. Any failure ignores the whole file.
3. **The digest moves out of the cursor namespace** to `cursors/digests/<safe(reader)>.json`.
   The cursor glob in `followers()` is not recursive, so the two never share a name. A legacy
   `<reader>.digest.json` is migrated on first load and then removed.
4. **Silent/stuck holds are watched, like held drains.** A held `campaign_silent` or
   `state_stuck` is recorded in the digest as a watch. When the campaign is still in flight and
   the event's age exceeds `gate_budget_s + 300 s`, the event is delivered once as a `wake`
   with its clock refreshed, and the watch is dropped. A watch whose campaign is no longer in
   flight is dropped without a wake.
5. **Tests** close the five test findings, named in the Test plan.

## Design

All paths are in `src/wt/agentic/` unless noted.

### 1. Replay (`quiet.py`, `events.py`)

- Add `Digest.reset()`: `pending = _fresh()`, `last_printed_last_id = 0`, `last_ping_fp = []`,
  `drains = []`, `watches = []`.
- No change to the brand-new-reader rule: without `--from-start`, a reader with no cursor file
  gets its cursor set to the end of the stream and replays nothing. With `--from-start` and no
  cursor file, that `cursor_set` is skipped and `cursor_get` stays 0, which is the replay case.
- In `follow`, after that brand-new-reader branch and before the loop, when `quiet` and
  `cursor_get(cfg, reader) == 0`: `Digest.load(...)`, `reset()`, `save()`. This runs once per
  follower start, not per poll. A cursor of 0 together with `last_printed_last_id > 0` cannot
  happen in normal operation, because a digest is printed only after the cursor passed its
  events. So the rule never discards state a healthy follower needs.
- Replay duplicates `hold` and `wake` records in `deliveries.jsonl`, as replay already does for
  wakes in non-quiet mode. This is accepted: a replay is an explicit operator action.

### 2. Validation (`quiet.py`)

Replace the shallow checks in `_FIELD_OK`:

- `held`: `dict[str, int]`.
- `campaigns`: `dict[str, list[str]]`.
- `merged`: `list[dict]`.
- `ping_items` and `last_ping_fp`: lists of two-element `[str, str]` lists.
- `watches`: list of dicts with `str` `key` and `type`, numeric `bound_s`, `dict` `event`.

`_well_typed` stays all-or-nothing. `Digest.load` already treats unreadable bytes
(`UnicodeDecodeError`, a `ValueError`) and a directory at the path (`OSError`) as absent; no
change there. `Digest.save` on a path that is a directory (so `os.replace` cannot succeed) logs
a warning and skips the write; it does not raise, and the follower keeps running with an
in-memory digest.

### 3. Digest file location (`quiet.py`, `events.py`)

- `Digest.load` and `Digest.save` use `E.cursors_dir(cfg) / "digests" / f"{E._safe(reader)}.json"`.
  `_atomic_write` creates the directory.
- Migration in `load`: if the new file is absent and `cursors/<safe>.digest.json` exists, read
  it, and use it only when it has no `after` key (a cursor always has one). `save` then writes
  the new path and unlinks the legacy file. A legacy file with an `after` key is a reader's
  cursor and is left alone.
- `E.followers`: replace the `p.name.endswith(".digest.json")` skip with a shape test: skip a
  `*.json` record that has no `after` key. This hides unmigrated legacy digests and no real
  reader, including one named `x.digest`.
- Grep `cursors_dir(` for every other consumer of the directory (`events.py`, `mailbox.py`);
  none may treat `digests/` as a reader.

### 4. Bounded silent/stuck holds (`quiet.py`, `events.py`)

- `classify` is unchanged for `campaign_silent` / `state_stuck`: it holds while `_silent_hold`.
- In `follow`, when such an event is held, call `ctx.digest.track_watch(cfg, ev)` next to the
  `track_drain` call. It stores `{"key": "<type>:<campaign>:<data.state>", "type", "bound_s":
  E.settings(cfg)["gate_budget_s"] + _GRACE_S, "event": ev}`, replacing an entry with the same
  key.
- `Digest.watch_wakes(ctx)`, called beside `drain_wakes`: for each watch, compute
  `age = ev.data.silent_s or stuck_s` plus `_age_s(ev.ts, ctx.now)`. If `_silent_hold(ev, ctx)`
  is false the watch is dropped. Else if `age > bound_s` the event is returned with the clock
  field set to `round(age)` and the watch is dropped; otherwise it is kept. The digest is saved
  before the lines print, as for drains. `follow` prints each, records a `wake` delivery, and
  counts it in `printed` and `max_events`.
- The lease is read only when a watch exists, as `drain_wakes` does.

## Alternatives considered

- **Keep the dedup, add a `--replay` flag.** Rejected: the lost-cursor case needs no flag, and
  cursor 0 identifies a replay exactly.
- **Rename the suffix only (`<reader>.digest.json` -> `<reader>.pending.json`).** Rejected: a
  reader named `x.pending` collides the same way. A separate directory removes the whole class.
- **Reject reader names ending in `.digest` at the CLI.** Rejected: it protects only one pair of
  names, and leaves any future file beside the cursors open to the same clash.
- **Bound the in-flight hold by age only, with no tracking.** Rejected: the watchdog event
  fires once, at about 900 s, so a stateless age test at classify time never sees an old enough
  event. A later wake needs tracking, which `drains` already models.
- **Make the watchdog re-fire silent/stuck events.** Rejected: it changes the always-on
  `events.jsonl` contract that SPEC-0300 promises not to touch.

## Acceptance criteria

- [x] A quiet follower started with `--from-start` for a reader with no cursor file, on a store
      whose digest file has `last_printed_last_id > 0`, folds every re-read held event into a
      digest and writes a `hold` delivery record for each; none is dropped.
- [x] The same holds when the reader's cursor file contains invalid JSON. A deleted cursor file
      without `--from-start` still starts at the end of the stream and replays nothing,
      unchanged.
- [x] With a non-zero cursor, the crash-recovery dedup is unchanged: an event at or below
      `last_printed_last_id` is not added twice.
- [x] A digest file with a wrong-typed element (`held` value, `campaigns` value, `merged`
      element, `ping_items` element, `last_ping_fp` element, `watches` element) or a non-UTF-8
      body is ignored; the follower runs and rewrites the file. A directory at the digest path
      is ignored on load, `save()` does not raise, and the follower keeps running.
- [x] The digest is stored under `cursors/digests/<safe(reader)>.json`. Followers named
      `conductor` and `conductor.digest` run side by side: neither overwrites the other's
      cursor or digest, and `E.followers` lists both.
- [x] A legacy `cursors/conductor.digest.json` holding a pending digest is loaded once, saved
      to the new path and removed. A legacy-named file that is a cursor (`after` key) is left
      in place.
- [x] A held `campaign_silent` or `state_stuck` for a campaign that stays in `lease.in_flight`
      produces exactly one `wake` line once its age exceeds `gate_budget_s + 300`, with
      `silent_s` / `stuck_s` refreshed, and a `wake` delivery record. Before the bound there is
      no line.
- [x] A watch whose campaign leaves flight is dropped with no line. A wake line counts toward
      `max_events`.
- [x] `tests/test_agentic_quiet.py` contains each test named in the Test plan, and each fails
      when the behavior it guards is removed.
- [x] `uv run pytest` passes with no change to any other spec's test.

### As shipped (2026-10-31)

Matches the Design, with these differences:

- **Replay trigger is narrower than "cursor is 0".** `follow` resets the digest only when
  `cursor_get == 0` **and** `last_printed_last_id > 0`. A cursor of 0 with a digest that never
  printed is a crash between the digest write and the first cursor write
  (`test_hold_crash_between_digest_and_cursor`); resetting there would record the hold twice, so
  `Digest.add`'s dedup keeps handling it. This is the case the Design's own argument covers
  ("cursor 0 with `last_printed_last_id > 0`").
- **Replay skips stale drains too.** `track_drain` / `track_watch` take a `now` that `follow`
  passes only during the first (replay) pass; an event whose `draining_s` / `silent_s` / `stuck_s`
  plus its age already exceeds its bound is folded into the digest but not tracked, so a replay
  cannot wake on history.
- **Bound counts only while alive.** `watch_wakes` keeps (without waking) a watch held only
  because its campaign waits behind a live close-train head; it wakes only when `_alive` for the
  campaign itself. `test_silent_watch_of_close_train_waiter_is_kept_without_waking`.
- **Tests use `silent_s=3600`** (the watchdog fires near `gate_budget_s`), so the bound is
  `3600 + 300` and does not collide with the 1800 s digest interval.
- `watch_wakes` / `drain_wakes` results are concatenated in `follow`; both save the digest before
  anything prints.

## Rollout / migration

1. Land code and tests; no config key changes.
2. The first quiet follower start after the upgrade migrates `conductor.digest.json` to
   `cursors/digests/conductor.json` (a pending digest survives the re-arm).
3. If the follower is re-armed on the old code afterward, it ignores the new directory and
   starts from a fresh digest: held events pending at that moment are lost once. Not an issue
   for a forward-only upgrade, so no downgrade path is provided.
