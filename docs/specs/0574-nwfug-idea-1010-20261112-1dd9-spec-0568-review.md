## Context

[SPEC-0568](./0568-nwfug-idea-909-20261104-2f87-spec-0415-review.md) (done) hardened
`tools/capture_history_fixture.py` and `tests/test_history_fixture.py`. Its review left
follow-up idea IDEA-1322 (from campaign IDEA-1010-20261112-1dd9): ten findings listed, four more
capped (`nw campaign show IDEA-1010-20261112-1dd9`). The triager waived most of them in that
campaign as nits or as intended behaviour. This spec takes the ones that are real, cheap to fix
and inside the same two files, and records a decision for each remaining one.

Findings and what this spec does with each:

1. **Budget headroom and test record unverified (AC9).** The pytest-affected gate runs with
   `-m 'not (integration or ...)'` and `tests/test_history_fixture.py` is marked `integration`, so
   the gate never ran the module; the SPEC-0568 test record has no measured time for the final
   test set. *Fix: run the module explicitly and record the measurement.*
2. **`SAFE_NAME_RE` accepts a trailing newline** (`tools/capture_history_fixture.py:69`): `$`
   matches before a final `\n`, so `_safe_name("SPEC-0001\n")` is true and the newline reaches a
   read path and an output key. *Fix: full-match.*
3. **Unhashable `spec_id` / `project` crash the capture** (`:565-566`): the `specs` / `projects`
   set comprehensions hash raw `state.json` values, so a list or dict value raises `TypeError`
   before `_safe_name` runs and the whole capture fails, not just that campaign.
4. **The unsafe-path test can plant a decoy outside its tmp dir** (`tests/test_history_fixture.py:1160-1180`):
   for `bad="/abs"` the decoy path normalises to `/abs` (or `/abs.last.json`), which a privileged
   runner can create.
5. **Budget guard flakiness and unguarded env parse** (`:53-63`): the summed test time is about
   15 s against a 20 s hard budget, and the two 20 000-string random corpus tests
   (`:1289`, `:1307`) are the largest share; `float(os.environ[...])` raises `ValueError` on a
   malformed override, at module teardown. (Also covers the capped "thin headroom" findings.)
6. **Common-word account names are not redacted in bare text.** After SPEC-0568 they are
   rewritten only as `/name`; `runner@localhost`, `USER=runner` and similar identifying forms
   survive.
7. **Common-word rule edge cases untested:** a mixed `users` set, case variants, and the
   `(?![\w.-])` boundary.
8. **Containment allows symlinks to unselected data elsewhere in `agentic/`** (`_inside(f, agentic)`):
   a link in `reviews/<spec_id>/` or `sentinel/` to `agentic/escalations/ESC-xxxx.json` or another
   campaign's files is read into the fixture.
9. **Containment root is all of `agentic/`** — the same issue as 8; one fix covers both.
10. **Email-rewrite reimplementation (`sub_emails`, `trim_cut`) is scope creep.** The reviewer
    asked for no change, and SPEC-0568's "As shipped" documents the deviation and its equivalence
    checks. **No action** (see Non-goals).

Capped findings: "the module-teardown wiring of the budget guard is not tested" is waived (the
manual budget step covers it; a subprocess test is costly) and stays so; "the source-digest guard
is never shown to fire" is taken (Decision 7).

## Goals / Non-goals

**Goals**
- A `spec_id` / `project` that is not a string, is unhashable, or carries a trailing newline never
  crashes the capture and never reaches a path; the campaign's other data is still captured.
- A review or sentinel file is read only if it resolves inside its own directory, so a symlink to
  other `agentic/` data is skipped with a note.
- A common-word account name is also rewritten in `name@host` and `USER=name` / `LOGNAME=name` /
  `USERNAME=name` forms, without rewriting ordinary prose or ordinary `key=value` config
  (`mode=test`, `--target=build`).
- `tests/test_history_fixture.py` has a lower summed time (headroom of at least 50 % under the
  budget on a quiet box), a guarded budget-env parse, and no test that can write outside its tmp dir.
- The new rules and the digest guard are shown to fire by tests; the module is run explicitly and
  its measured result is recorded.

**Non-goals**
- Reverting or restructuring `sub_emails` / `trim_cut` (finding 10); the committed fixture,
  `MANIFEST.json`, `EMAIL_RE`, `scan`, and the host/IP/secret/`env` rules stay as they are.
- A subprocess test of the module-teardown wiring of the budget guard.
- Redacting a common-word name that appears as free prose or as an `ls` owner column
  (`runner runner`): prose and owner columns cannot be told apart from ordinary words, which is
  why SPEC-0568 made the rule path-segment-only. That trade-off stands.
- Any change under `src/nightwright/` or to files other than the tool, its test module and this spec.

## Decision

1. **Names are validated with `fullmatch`.** `_safe_name` uses `SAFE_NAME_RE.fullmatch` (the
   regex loses its `^`/`$` anchors), so a trailing newline is rejected like any other bad character.
2. **Non-string and unhashable ids are dropped before they are hashed.** `specs` and `projects`
   are built from values that are `str` only; any other non-`None` value (list, dict, number)
   emits a `note(f"unsafe spec_id {v!r}: skipped")` / `note(f"unsafe project {v!r}: skipped")`
   and nothing else. `None` stays skipped silently, as before.
3. **Containment is per file or per directory, whichever is exact.** A file in
   `reviews/<spec_id>/` is read only if its resolved path is inside
   `(agentic/"reviews").resolve() / spec_id` (a root check with `_inside`). Because that root is
   built from the resolved parent plus the validated name, a `reviews/<spec_id>` directory that is
   itself a symlink to elsewhere in `agentic/` fails the check for every file in it. The sentinel
   file is **not** a root check: `sentinel/` holds every project's file, so a root of
   `sentinel/` would accept a symlink `sentinel/A.last.json -> sentinel/B.last.json`. The
   sentinel file is read only if `f.resolve() == (agentic/"sentinel").resolve() / f"{proj}.last.json"`
   (an equality check against the one expected path); a symlink to any other file, including
   another project's file in the same directory, is skipped. A failing file is skipped with the
   "resolves outside" note (for the sentinel call site the note text reads
   `sentinel/<project>.last.json does not resolve to itself: skipped`). This narrows SPEC-0568's
   Decision 5 (root: all of `agentic/`) and keeps its AC4 true; it does not contradict it.
4. **Common-word names gain two identifying contexts.** Besides `/name` (rewritten to `/user`),
   a name in `COMMON_WORD_USERS` is rewritten to `user` when it is immediately followed by `@`
   (`runner@localhost`), or when it is the value of one of the identity variables `USER`,
   `LOGNAME` or `USERNAME` (`USER=runner`; the variable name is case-sensitive and starts at a
   word boundary). A generic `=name` context is **not** used: `COMMON_WORD_USERS` holds words such
   as `test`, `build`, `ci`, `service`, `agent`, `worker`, `deploy`, `docker`, `dev`, `admin`, and
   `mode=test`, `--target=build`, `env=ci` are ordinary config, not account names. Both new
   contexts use the same `(?![\w.-])` / `(?<![\w.-])` boundaries as the path rule. All other bare
   occurrences stay. `scan` is unchanged.
5. **The budget is kept at 20 s and made robust, not raised.** The two random email-corpus
   tests shrink their corpora (20 000 to 4 000 strings; the seeds, alphabets and the
   equivalence assertion are unchanged, so the property checked is the same), and the summed time
   of the module must be at most 10 s on a quiet box. `check_budget` parses the env override with
   a guard: a value that is not a positive finite number fails with a message naming
   `NW_HISTORY_FIXTURE_BUDGET_S` and the bad value (an `AssertionError`, not a bare `ValueError`).
6. **Tests cannot write outside their tmp dir.** `test_unsafe_spec_id_and_project_are_skipped`
   plants its decoy only when the normalised path is inside `tmp_path`; otherwise it plants none
   (the assertion that no file is read for that value still holds, because nothing exists there).
7. **The digest guard is a function that is shown to fire.** The comparison in the `captured`
   fixture teardown becomes `assert_tree_unchanged(src, digest)`; a test mutates a tmp copy and
   expects it to raise.
8. **The module is run explicitly and the result is recorded** in this spec's test record, since
   the gate skips `integration` tests.

## Design

**`tools/capture_history_fixture.py`**
- `_safe_name(v)`: `isinstance(v, str) and SAFE_NAME_RE.fullmatch(v) is not None and v not in (".", "..")`.
  Keep `SAFE_NAME_RE` as a `re.compile(r"[A-Za-z0-9][A-Za-z0-9._-]*")` (no `^`/`$`).
- `collect_records`: replace the two set comprehensions with a small helper
  `_names(values, kind, note)` that returns a set of the `str` values, skips `None` silently and
  notes everything else that is not a `str` (so nothing is ever hashed unless it is a `str`).
  The existing `_safe_name` check and notes for strings stay.
- Containment: `_inside(f, root)` is unchanged and stays for the reviews files; its call site
  passes `(agentic / "reviews").resolve() / s` as the root. The sentinel call site drops `_inside`
  and uses an equality check instead: read `f` only if
  `f.resolve() == (agentic / "sentinel").resolve() / f"{proj}.last.json"` (`proj` is already
  validated by `_safe_name`). A root check is wrong there because other projects' files live in the
  same directory; the equality check rejects `sentinel/A.last.json -> sentinel/B.last.json`.
- `Sanitizer.__init__`: for a name in `COMMON_WORD_USERS` the `user_res` entry becomes a list of
  `(regex, replacement)` pairs (names passed through `re.escape`): `/name(?![\w.-])` -> `/user`,
  `(?<![\w.-])name(?=@)` -> `user`, and, as a capture-group substitution because a lookbehind
  cannot hold a variable-width alternation, `\b(USER|LOGNAME|USERNAME)=name(?![\w.-])` ->
  `\1=user`, compiled without `re.IGNORECASE`. Counting stays under `user_name`.

**`tests/test_history_fixture.py`** (existing module with its one marker
`pytestmark = pytest.mark.integration`; no new module, no second tier marker)
- `check_budget`: guarded parse (above). Corpora of the two `_email_corpus` tests: 4 000.
- `test_unsafe_spec_id_and_project_are_skipped`: decoy planted only if inside `tmp_path`; new
  parameters: `"SPEC-0001\n"`, and (separately, a new test) non-string values.
- `assert_tree_unchanged(src, digest)` helper plus its firing test.
- New tests as listed in the Test plan.

## Alternatives considered

- **Raise the budget to 30 s** — hides the headroom problem instead of fixing it, and weakens the
  SPEC-0415 AC10 bound.
- **Mark the corpus tests `perf` or drop them** — they pin the `sub_emails` / `EMAIL_RE`
  equivalence; a smaller corpus keeps that check.
- **Narrow containment by a second `reviews/<spec_id>` realpath check only** — the
  resolved-parent-plus-name root is the same idea with one line and handles a symlinked
  `<spec_id>` directory too.
- **Rewrite every bare occurrence of a common-word name** — the choice SPEC-0568 rejected;
  prose such as "the runner log" would be mangled.
- **A generic `(?<==)name` context** — would turn `mode=test`, `--target=build` and `env=ci`
  into `=user`; only `USER=` / `LOGNAME=` / `USERNAME=` identify an account.
- **A `sentinel/` root check** — accepts a symlink to another project's sentinel file, which is
  the leak finding 8 describes; an equality check against the one expected path does not.

### As shipped (2026-11-12)

- Design followed, with these deviations and additions:
  - `_inside(path, root)` no longer calls `root.resolve()`: the Design's "resolved parent plus name"
    root only rejects a symlinked `reviews/<spec_id>` directory if the root is left unresolved. Callers
    pass an already resolved root. `_inside` also resolves with `strict=True` for any path that exists
    or is a link: on Python 3.13+ a non-strict `resolve()` no longer raises on a symlink loop, which
    made `test_inside_treats_a_symlink_loop_as_outside` and the `loop` case of
    `test_review_dir_symlinks_and_loops_are_skipped` fail on `main` under Python 3.14. A dangling link
    in `reviews/` is therefore now noted as skipped.
  - The reviews skip note reads `... resolves outside its own directory: skipped`; the sentinel note
    reads `sentinel/<project>.last.json does not resolve to itself: skipped`. The existing sentinel
    test matches on `skipped` instead of `outside`.
  - Scope of Decision 2: `spec-reviews.jsonl` filtering (`o.get("spec_id") in specs`) is also guarded
    with `isinstance(..., str)`, so a hostile row cannot raise there. The `state` hash at
    `c.state.get("state") in CANDIDATE_STATES` is out of scope (a follow-up).
  - `test_check_is_independent_of_the_running_user` is one test (four parallel subprocesses) instead
    of four parametrised cases.
  - `check_budget` rejects any value that is not a positive finite number; the message quotes the raw
    value with `!r`.
- Test-budget changes beyond Decision 5 (the Decision 5 fallback: trim the next-slowest tests found
  with `--durations=0`, no test or assertion removed):
  - `run_tool(...)` now calls `main(args)` in-process with the same env handling and a
    `CompletedProcess`-shaped result; the old subprocess form is `run_tool_cli`, kept for the
    `captured` fixture capture, `--help` / stdlib-only start, `test_committed_fixture_matches_manifest`
    and `test_check_is_independent_of_the_running_user` (so the CLI contract is still exercised as a
    real subprocess).
  - `_clean` runs `EMAIL_RE` only over the `"@"`-bearing tokens of the text (a match needs an `@` and
    cannot cross a character outside its set), the same assertion without the quadratic scan.
- AC7's 10 s figure is verified as a same-load ratio against `main` plus a sub-10 s reading at load 9.6;
  no quiet-box reading was available.
