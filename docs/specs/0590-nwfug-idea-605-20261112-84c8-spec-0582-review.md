## Context

[SPEC-0582](./0582-shell-autocomplete-gaps-many-dynamic-value-args.md) made the SPEC-0039
shell-completion guard live: `has_completer`, `missing_required_shell_completes`,
`missing_dynamic_completes` and `stale_exemptions` in `src/nightwright/completion.py`, with the
`UNCOMPLETED_EXEMPT` ratchet. Its review (IDEA-605 audit follow-up, idea IDEA-1341) found four
minor test gaps, all in `tests/test_completion.py`. The shipped behavior is correct; the tests
would not notice some regressions:

1. **Docs / comment AC has no automated test** (`nwfu:7c6911e4a825`). The `docs/WORKFLOW.md`
   "Shell completion" checklist and the comment above `REQUIRED_SHELL_COMPLETE_NAMES`
   (`completion.py:31-35`) describe the default-deny rule and the exemption ratchet, but only a
   reviewer checks that; nothing fails if they regress.
2. **The File case is masked** (`nwfu:d56df651810d`).
   `test_default_deny_ignores_non_string_params` names its `click.File` option `--blob`, and
   `blob` is in `FREE_TEXT_NAMES` (`completion.py:74`), so the name filter would skip it even if
   `File` were wrongly treated as a string param.
3. **`has_completer`'s type and flag branches are untested for the required-name check**
   (`nwfu:7c6c48141b4c`). The `missing_required_shell_completes` fixtures only use plain string
   params. No test puts a `REQUIRED_SHELL_COMPLETE_NAMES` name (e.g. `project`) on a `Choice`,
   `Path` or flag option, so dropping a branch from `has_completer` would only surface through
   the dynamic (default-deny) guard, if at all.
4. **`stale_exemptions` edge cases are untested** (`nwfu:efc6b0caeea4`). Only the wired-completer
   and missing-command cases are tested. A key pointing at an existing param that is now a flag,
   `Choice`, `Path` or non-string type is reported by the live-set logic
   (`completion.py:654-661`) but is not covered.

## Goals / Non-goals

**Goals**
- Each of the four findings gets an automated test that fails if the behavior it describes
  regresses.
- All new tests extend the existing `tests/test_completion.py`.

**Non-goals**
- No change to `src/nightwright/completion.py` behavior, `docs/WORKFLOW.md` wording,
  `FREE_TEXT_NAMES`, `UNCOMPLETED_EXEMPT`, or any command or completer. If a new test exposes a
  real bug it is reported, not silently fixed here.
- No new test module and no new speed-tier marker.
- Wiring completers or the group tab-completion fix (still separate follow-ups of SPEC-0582).

## Decision

Add tests only, in `tests/test_completion.py` (which already carries its one module marker
`pytestmark = pytest.mark.fast`):

1. A docs test reads `docs/WORKFLOW.md` and the `completion.py` source and asserts the required
   phrases are present.
2. Rename the File option in `test_default_deny_ignores_non_string_params` to a name that is not
   in `FREE_TEXT_NAMES` and add a guard assertion that none of that test's option names are
   free-text names, so the mask cannot return.
3. Add a parametrized required-name test that puts `project` on a string-typed flag
   (`is_flag=True, flag_value="x"`, so the BOOL type cannot mask the flag branch), a plain bool
   flag, `Choice`, `Path`, numeric, bool and `DateTime` params (no report) and on a plain string
   param (reported).
4. Add a parametrized `stale_exemptions` test for keys that name an existing param that is a
   string-typed flag, plain bool flag, `Choice`, `Path`, numeric, bool, `DateTime`, `File` or
   other non-string type (reported), plus a still-live uncompleted string param (not reported).

## Design

All edits are in `tests/test_completion.py`, reusing the existing `_fixture_group` and
`_stub_complete` helpers.

- **Docs test (`test_completion_docs_describe_default_deny_and_ratchet`).** Read
  `docs/WORKFLOW.md` (path from `Path(__file__).resolve().parents[1] / "docs" / "WORKFLOW.md"`)
  and slice the text from the `## Shell completion` heading to the next `## ` heading. Assert
  the slice contains `SPEC-0582`, `default-deny`, `FREE_TEXT_NAMES`, `UNCOMPLETED_EXEMPT`,
  `ratchet` and `stale_exemptions`. Read `src/nightwright/completion.py` (via
  `Path(C.__file__)`), take the contiguous `#` comment lines directly above the line starting
  `REQUIRED_SHELL_COMPLETE_NAMES = `, and assert they contain `SPEC-0582`, `missing_dynamic_completes`,
  `FREE_TEXT_NAMES` and `UNCOMPLETED_EXEMPT`. Phrase checks are case-insensitive substring
  matches so wording tweaks do not break the test, while deleting the rule does.
- **File case.** In `test_default_deny_ignores_non_string_params`, rename `--blob` to
  `--attachment`. Add, inside the test, `assert not {"flag", "path", "choice", "num", "ratio",
  "yes_no", "when", "attachment", "uid", "pair"} & C.FREE_TEXT_NAMES` (the param names Click
  derives from the options) so a future `FREE_TEXT_NAMES` addition that masks one of these names
  fails the test instead of silently weakening it. A second, tiny test
  (`test_default_deny_file_param_not_masked_by_free_text`) monkeypatches `FREE_TEXT_NAMES` to
  `frozenset()` and `UNCOMPLETED_EXEMPT` to `{}` and asserts a lone `click.File` option, a
  `click.UUID` option and a `click.Tuple` option report nothing, proving the type check, not
  the name filter, is what skips them.
- **Required-name type and flag branches
  (`test_required_name_ignores_params_with_type_completion`).** Parametrize over `(factory,
  expected)`: a string-typed flag `click.Option(["--project"], is_flag=True, flag_value="x")`
  (Click 8 gives a flag with no `flag_value` the BOOL type, which `has_completer` accepts through
  `BoolParamType` and `_is_string_param` rejects through its type check, so a plain
  `is_flag=True` cannot isolate the `is_flag` branch; with `flag_value="x"` the param type is
  `StringParamType` and only the `is_flag` branch skips it), a plain
  `click.Option(["--project"], is_flag=True)` kept as an extra bool-flag case,
  `click.Option(["--project"], type=click.Choice(["a", "b"]))`,
  `click.Argument(["project"], type=click.Path())`,
  `click.Option(["--project"], type=click.INT)`, `click.Option(["--project"], type=click.FLOAT)`,
  `click.Option(["--project"], type=click.BOOL)`, `click.Option(["--project"],
  type=click.DateTime())` all expect `[]`; a plain `click.Option(["--project"])` expects
  `["sub:project"]`. For the string-flag case the test first asserts
  `isinstance(param.type, click.types.StringParamType)` and `param.is_flag`, proving the type does
  not mask the flag branch. Monkeypatch `UNCOMPLETED_EXEMPT` to `{}`. Assert both
  `C.has_completer(param)` and `C.missing_required_shell_completes(grp)`, so each branch of
  `has_completer` is exercised through the required-name path. Because the factories are built
  inside the test (Click params are mutable), parametrize over lambdas or ids.
- **`stale_exemptions` edge cases
  (`test_stale_exemptions_reports_existing_non_string_or_typed_params`).** Build a fixture tree
  with options `--flagged` (string-typed flag: `is_flag=True, flag_value="x"`, with the same
  `StringParamType` and `is_flag` assertions as above so the BOOL type does not mask the flag
  branch), `--switch` (plain `is_flag=True` bool flag), `--picked` (Choice), `--located` (Path), `--counted` (INT),
  `--ratio` (FLOAT), `--toggle` (BOOL), `--when` (DateTime), `--attachment` (File) and
  `--live` (plain string, no completer). Monkeypatch `UNCOMPLETED_EXEMPT` with one entry per
  param, each `"sub:<name>": "reason"`. Assert `C.stale_exemptions(grp)` equals the sorted list of
  every key except `sub:live`. Add a second case where an exemption key names a param whose
  command exists but whose param name does not (`sub:nonexistent`), expecting it reported.

Every test uses only fixture Click trees and monkeypatching, so the module stays in the `fast`
tier.

## Alternatives considered

- **Assert docs wording with exact sentences** — brittle; phrase presence per section is enough
  to catch removal of the rule.
- **Fix the comment/doc drift only by review** — that is the status quo the finding rejects.
- **Remove `blob` from `FREE_TEXT_NAMES`** — changes shipped behavior for a real name; renaming
  the fixture option plus a mask guard fixes the test without touching the code.
- **A new test module for the guard edge cases** — would add a second marker site for no gain;
  extending `tests/test_completion.py` keeps one tier marker.

## Acceptance criteria

- [ ] A test fails if the `docs/WORKFLOW.md` "Shell completion" section loses `default-deny`,
      `FREE_TEXT_NAMES`, `UNCOMPLETED_EXEMPT`, `ratchet`, `stale_exemptions` or the SPEC-0582
      reference, and passes on the current docs.
- [ ] A test fails if the comment block above `REQUIRED_SHELL_COMPLETE_NAMES` loses the
      default-deny / `missing_dynamic_completes` / `FREE_TEXT_NAMES` / `UNCOMPLETED_EXEMPT`
      description, and passes on the current comment.
- [ ] The non-string test's File option is named outside `FREE_TEXT_NAMES`, the test asserts no
      fixture option name is a free-text name, and a separate test with `FREE_TEXT_NAMES` emptied
      proves `File`, `UUID` and `Tuple` options are skipped by type.
- [ ] `missing_required_shell_completes` returns `[]` for a `project` param that is a
      string-typed flag (`is_flag=True, flag_value="x"`, asserted to have `StringParamType`), a
      plain bool flag, `Choice`, `Path`, numeric, bool or `DateTime`, and `["sub:project"]` for a
      plain string `project`; `has_completer` agrees in each case.
- [ ] `stale_exemptions` reports a key for each existing param that is now a string-typed flag
      (`flag_value="x"`, asserted `StringParamType`), plain bool flag, `Choice`, `Path`, numeric,
      bool, `DateTime` or `File`, reports a key whose param name does not exist, and does not
      report a key for a still-live uncompleted string param.
- [ ] `src/nightwright/completion.py`, `docs/WORKFLOW.md` and all CLI/completer behavior are
      unchanged by this spec (`git diff` touches only `tests/test_completion.py`).
- [ ] No new test module and no second `pytestmark` in `tests/test_completion.py`.

## Test plan

- **Automated tests** (extend `tests/test_completion.py`; it already has its single module-level
  marker `pytestmark = pytest.mark.fast`, so the tier stays `fast` and no second marker is added):
  - `test_completion_docs_describe_default_deny_and_ratchet` (AC1, AC2).
  - `test_default_deny_ignores_non_string_params` (renamed File option plus mask guard) and
    `test_default_deny_file_param_not_masked_by_free_text` (AC3).
  - `test_required_name_ignores_params_with_type_completion`, parametrized over a string-typed
    flag (`flag_value="x"`), a plain bool flag, `Choice`, `Path`, `INT`, `FLOAT`, `BOOL`,
    `DateTime` and a plain string control (AC4).
  - `test_stale_exemptions_reports_existing_non_string_or_typed_params` (AC5).
  - Run: `uv run pytest tests/test_completion.py -q` passes.
  - `python3 tools/test_tiers.py --check` exits 0 (`tools/test_tiers.py` exists; no new module).
- **Mutation checks (manual, one per finding or branch; revert each afterwards):**
  1. Delete the word `ratchet` from the `docs/WORKFLOW.md` completion section; the docs test
     fails.
  2. Remove `click.Choice` from `has_completer`'s type tuple; the new required-name test fails
     on the `Choice` case.
  3. Change `_is_string_param` to `isinstance(param.type, (StringParamType, click.File))`; the
     File-skip test fails even with `blob` unrelated.
  4. Change `stale_exemptions` to treat every existing param as live; the new stale test fails.
  5. Remove the `is_flag` branch from both `has_completer` and `_is_string_param`; the
     string-flag (`flag_value="x"`) cases in the required-name and stale tests fail, while the
     plain bool-flag cases still pass (they are masked by the BOOL type, which is why the
     string-flag case exists).
- **Regression guard:** `python3 tools/affected_tests.py --run uv run pytest -q` (tests only
  changed, so affected set is `tests/test_completion.py`) and `python3 tools/spec_lint.py` exit 0;
  `git diff --stat` shows only `tests/test_completion.py` (plus this spec and generated ledger).
