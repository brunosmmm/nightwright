## Goals / Non-goals

**Goals**
- E4 never silently turns an unreadable exit timestamp into "still parked".
- E5 has no lower bound unless all three measurement specs are merged, as SPEC-0304 says.
- "Opened after the qualifying point" means the same thing for `qualifying` and for E5.
- E6 session order does not depend on registry order when one session resumes another.
- Each of the ten findings has a test that fails if the behavior regresses.

**Non-goals**
- Any change to the exit criteria, targets, JSON schema `nw.conductor.mvp.v1` (new values are
  only added to the free `status` field of `parks_undecided` rows) or the CLI options.
- The IDEA-461 follow-ups, and the findings SPEC-0304's review waived.
- Reworking `conductor_cost.transcript_marks`.

## Decision

Make the four code changes below, each the smallest edit that meets the finding, and add the
tests for all ten findings to `tests/test_agentic_mvp_report.py`.

1. **E4: an unreadable exit ts is `unverified`, never covered.** Find the first
   `transition` with `from: PARKED` after the park (by `seq`, as today) and keep it even when
   its `ts` does not parse. If that transition exists and its ts is unparseable, the park is
   reported with status `unverified` and does not count as covered. "No such transition yet"
   (still PARKED) is unchanged: covered when a decision exists.
2. **E5: no lower bound unless all three measurement specs are merged.** `report` passes
   `None` as E5's point when `qualifying_point` lists any missing spec.
3. **Opened at the qualifying point is not after it.** A campaign qualifies only when it
   opened strictly after the point. `e5` therefore skips `opened <= point` (it skips
   `opened < point` today), matching `qualifying`'s `start <= point` test.
4. **E6 orders resumed sessions by containment.** The sort key of a registered session is
   `(first-turn ts, depth, registry order)`, where `depth` is the number of other registered
   sessions whose non-empty set of message ids is a proper subset of this session's ids. A
   session that contains another's history therefore always sorts after it, whatever the
   turn counts or the registry order. Unrelated sessions with equal first ts and equal depth
   keep registry order. This replaces the turn-count tie-break.

## Design

All edits are in `src/nightwright/agentic/mvp_report.py`.

- **E4 (`e4`).** Replace the `next(D.parse_ts(...) for ...)` expression with a lookup of the
  exit transition record (`exit_tr = next((x for x in led if x.get("type") == "transition"
  and x.get("from") == "PARKED" and (x.get("seq") or 0) > (e.get("seq") or 0)), None)`), then
  `exit_ts = D.parse_ts(exit_tr.get("ts")) if exit_tr else None`. Status:
  `missing` when there is no hit; else `unverified` when `exit_tr` is not None and `exit_ts`
  is None; else `late` when `hit ts > exit_ts`; else covered. `unverified` rows go to
  `parks_undecided` like `missing` and `late` ones, and `render_text` already prints the
  status string as is. The detail line of E4 stays "N of M parks decided before the campaign
  left PARKED".
- **E5 lower bound (`report`).** `point, missing = qualifying_point(all_merged)`;
  `e5(cfg, None if missing else point, targets)`. `qualifying_point` and `qualifying` keep
  their signatures and results (both already use `missing`).
- **Boundary (`e5`).** `if point is not None and (opened is None or opened <= point): continue`.
  The docstring says "opened after `point`". A campaign with no parseable open ts stays
  excluded when a point exists.
- **E6 order (`e6`).** After the per-session `(first ts, turn count, order, sid, path, turns)`
  tuples are built, compute each session's message-id set (`msg_id` values that are not
  `None`). `depth[s]` = count of other sessions `t` with `ids[t]` non-empty and
  `ids[t] < ids[s]` (proper subset). Sort by `(first ts, depth[s], order)`. The turn count is
  no longer part of the key. Everything after the sort (replay detection, restart dating by
  first new turn, `transcript_marks(path, replayed)`) is unchanged. Subset implies depth
  `depth[sub] < depth[super]` because anything below the subset is below the superset too, so
  the key is a total order.
- **Docs.** In SPEC-0304, append one line to *As shipped* pointing to this spec as the place
  where the E5 bound, the qualifying boundary, the `unverified` status and the E6 ordering
  were amended. No other SPEC-0304 text changes.

### Tests (all in `tests/test_agentic_mvp_report.py`)

Use the existing helpers (`camp`, `park_ev`, `out_of_park`, `decide`, `asst`, `compact`,
`conductor`, `deliveries`, `pr_project`, `undecided_event`, `one_window`, `run`).

1. `test_since_filters_on_open_ts`: three campaigns, `A` opens day 4 and ends day 8, `B`
   opens day 6 (exactly the cutoff, midnight UTC) and ends day 8, `C` opens day 7 and ends
   day 9. `report(cfg, n=3, since=day 6)` returns `["B", "C"]`: `A` ends after the cutoff, so a
   filter on end ts would keep it; `B` is kept because the bound is inclusive.
   Through the CLI: `--since 2026-10-06 --json` gives the same set, and `--since
   2026-10-06T12:00:00+00:00 --json` gives `["C"]`.
2. `test_e5_escalation_alone_leaves_e5_passing`: a PR-policy campaign merged with
   `pr_state: MERGED`, no park, and one escalation (`ESC._create`) → E5 `pass`, its row
   `status: pass`, and the escalation listed in `touchpoints`.
3. `test_e3_delivery_exactly_at_start_counts_and_before_start_does_not`: with deliveries only
   before `start` the result is value 0 and `pass` (kept from the existing test); one
   non-hold delivery exactly at `start` gives value 1, and one at `end` too gives value 2
   over 1 merge, both inside the closed interval.
4. `test_e4_unparseable_exit_ts_is_unverified`: a campaign parked once, resumed with a
   `from: PARKED` transition whose `ts` is `"garbage"`, and a decision after the park →
   E4 status `fail`, value 0, the park listed with status `unverified`. A twin campaign still
   PARKED (no exit transition) with a decision stays covered.
5. `test_e5_has_no_lower_bound_with_a_measurement_spec_unmerged`: only SPEC-0299 and
   SPEC-0300 campaigns merged (late, day 10), a merged PR campaign opened day 2 → E5 `pass`,
   value 1. With SPEC-0301 merged as well, at day 10, the same campaign is before the point
   and E5 is `fail`.
6. `test_e6_resumed_session_ordering_is_registry_independent`: original `sO` with turns
   `a, b, c, d` (compaction and brief inside the interval) and a resumed `sR` with turns `a,
   b, c, x` (same first ts, fewer turns than `sO`, since `sO` kept running). Registered in
   both orders (two temp configs, or the registry re-created), the events are identical:
   `sO`'s compaction and a restart for `sR` dated at `x`, none the other way round.
7. `test_cli_empty_store_exits_zero_with_null_values` (extends
   `test_cli_empty_store_and_since`): on an empty store `run()` exits 0 and `run("--json")`
   exits 0 with `window.start`/`end` null, `merges` 0, `qualifying` false, every criterion's
   `value` null and status `no_data` except E5 (value 0, status `fail`), and `ok` false.
8. `test_e6_clean_interval_open_lower_bound`: a `park_undecided` stamped exactly at the event
   ts leaves the event clean, and one stamped before it does too (while +15 min stays not
   clean, as in `test_e6_clean_upper_bound`).
9. `test_e5_campaign_opened_exactly_at_the_qualifying_point`: a PR campaign opened at the
   instant the last of SPEC-0299/0300/0301 ended is not counted by E5 (`fail`, value 0); one
   opened a second later is. A window campaign opened at that instant gives
   `qualifying: false` with the campaign named in the reason, so the two agree.
10. `test_e6_compaction_outside_interval_and_inclusive_ends`: a `compact_boundary` before
    `start` and one after `end` produce no events; one exactly at `start` and one exactly at
    `end` are events.

## Alternatives considered

- **Treat an unparseable exit ts as `late`.** It claims the decision was too slow, which
  nothing shows. `unverified` says what is known.
- **Fall back to `seq` order between decision and exit when the ts is bad.** Decisions carry
  their own `seq` in a different file, so it cannot be compared with the ledger's.
- **Keep a lower bound for E5 from the partial point.** It hides a PR campaign merged before
  the last measurement spec, with no benefit: E5 also fails closed when no spec is merged.
- **Make `qualifying` inclusive (`start < point` is early) instead of changing E5.** The
  epic says campaigns "start after" the measurement specs merge, so a campaign opened at the
  point is not after it.
- **Break E6 ties by session id.** Rejected in SPEC-0304's fourth review round: a resumed
  id can sort before the original's.

## Acceptance criteria

- [ ] `nw queue mvp-report` reports a park whose first `from: PARKED` transition has an
      unparseable ts as `unverified` in `parks_undecided`, E4's value counts it as not
      covered, and a park whose campaign has no exit transition yet is still covered by a
      decision.
- [ ] E5 applies no lower bound while any of SPEC-0299, SPEC-0300 or SPEC-0301 has no merged
      campaign.
- [ ] A campaign opened exactly at the qualifying point is excluded by E5 and makes the
      window not qualifying, with the same reading in both.
- [ ] E6 yields the same events whichever order two sessions that share history are
      registered in, including when the original session has more turns than the resumed
      one, and a resumed session is never ordered before the session whose ids it contains.
- [ ] `--since` is tested with a campaign that opens before the cutoff and ends after it
      (excluded) and one that opens exactly at the cutoff (included), through the API and the
      CLI with a date and with a datetime.
- [ ] A test shows an escalation alone leaves E5 `pass`, with the escalation listed.
- [ ] A test pins E3's closed interval ends and the "only deliveries before `start` → value 0,
      `pass`" case.
- [ ] A CLI test shows an empty store exits 0 for text and `--json`, with null values and
      `no_data` statuses (E5 `fail`, value 0) and `ok: false`.
- [ ] A test shows a `park_undecided` at or before the event ts leaves it clean and one at
      +15 min does not.
- [ ] Tests show a compaction outside `[start, end]` is no event and one exactly at each end
      is.
- [ ] No change to `nw.conductor.mvp.v1` keys, to the criteria targets or to the CLI options.

  test 5; `opened < point` restored in `e5` fails test 9; sorting E6 by
  `(first ts, turn count, order)` fails test 6; `pick_window` filtering on `c["end"]` fails
  test 1; `ts <= u` in the clean check fails test 8.
- **Manual verification**: on the live store run `nw queue mvp-report --json` before and after
  the change. E1–E3 and E6 are unchanged; E5 and the `parks_undecided` list change only in
  the cases above (none expected on the current data).

  and `tests/test_agentic_decisions.py` are untouched and pass; `python3 tools/spec_lint.py`
