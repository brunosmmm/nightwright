## Context

[SPEC-0569](./0569-nw-spec-reserve-does-not-prevent-collisions-spec.md) made the spec-number
allocator (`src/nightwright/spec_numbers.py`) scan remote-tracking refs as well as local
branches, and added `collisions()`, `number_taken()` and `nw spec check-numbers`. Its review left
five minor findings (IDEA-1325, from IDEA-1074):

1. **Docs guard gap** (`tests/test_spec_numbers.py:617`). `test_contract_docs_name_the_allocator_and_the_check`
   asserts `nw spec reserve`, `nw spec check-numbers` and the absence of `(next free number)` in
   `AGENTS.md` and `docs/README.md`, but not `--from-idea`, which the acceptance criterion also names.
2. **Queue test gap** (`tests/test_agentic_spec_writer.py:974`).
   `test_uncommitted_collision_before_start_releases_and_reallocates` folds the old/new
   reservation state into one tuple compared in a `before` hook, and never checks the state
   after the writer has run, up to the commit. A regression that re-created the released
   reservation 2 later in the run would pass.
3. **Scan cost.** `_scan_refs` (`spec_numbers.py:73`) returns every `refs/heads/` and
   `refs/remotes/` ref and `_ref_files` (`:82`) runs one `git ls-tree` per ref. `allocate` runs
   `_prune` (one full scan) and then `_branch_numbers` (a second full scan); `list_reservations`
   and `release` run `_prune`, so even with no reservation they pay a full scan. With remotes
   the ref count roughly doubles, and most remote-tracking refs point at the same commit as a
   local branch.
4. **`collisions()` is not read-only in practice** (`:270`). Its docstring says it never writes
   the store, but it enters `_locked(cfg)`, which creates `data_dir` and `spec-reservations.lock`
   and blocks behind any concurrent `allocate`. `_save` is an atomic `os.replace`, so a lock-free
   read of the store is safe.
5. **Own-branch rename reported as a collision.** `collisions()` excludes only the tree's own
   worktree location (`worktree:<tree>`). The tree's own branch ref (`main`, `nw/<id>`) is still
   compared, so a spec file renamed (new slug, same number) but not yet committed on that
   branch is reported as colliding with its own committed old filename.

## Goals / Non-goals

**Goals**
- Close all five findings with unit-level tests.
- Cut git subprocesses per scan to one `ls-tree` per distinct commit, one scan per public call, and zero scans when nothing needs pruning.
- Make `collisions()` genuinely read-only: no directory creation, no lock file, no blocking.
- Stop reporting a slug rename on the tree's own branch (and its upstream) as a collision.

**Non-goals**
- Changing allocation order, the store schema, the `nw spec reserve|release|check-numbers` surface or JSON shapes.
- Changing the queue's retry loop ([SPEC-0569] behaviour) beyond the test.
- Ignoring *other* branches or remotes that carry the number under a different slug (still a collision).

## Decision

Fix all five in one small spec, in `spec_numbers.py` plus tests: dedupe ref scans by commit and
scan once per call; make `collisions()` read the store without the lock; skip the tree's own
branch and its upstream ref in the filename comparison; tighten the two tests.

## Design

**Scan cost (`spec_numbers.py`).**
- `_scan_refs(top)` runs one `git for-each-ref --format='%(refname) %(objectname)'` over both prefixes (still skipping `*/HEAD`) and returns `[(ref, sha)]`.
- `_ref_files(top, rel_dir, sha, cache)` memoises `git ls-tree` by commit `sha` in a per-scan dict, so refs that share a commit cost one subprocess.
- A small `_RefScan` value (built once per public call: refs, per-ref filenames) is passed to `_branch_numbers`, `_number_files` and `_prune`. `allocate` builds it once and reuses it for both the prune and the `used` set. Local-ref and remote-ref results stay distinguishable (ref name kept) so location reporting is unchanged.
- `_prune` builds the scan lazily and only when some record has `r["key"] == key`; with no such record it runs no git command. `list_reservations` and `release` thereby run no `ls-tree` when the store holds nothing for the key.

**Read-only `collisions()`.** It drops `with _locked(cfg)` and calls `_load(cfg)` directly, then prunes in memory with the shared scan (never `_save`). A missing store reads as `[]` (existing `_load` behaviour); no directory or lock file is created. Torn reads are impossible because `_save` replaces atomically. A concurrent allocate may be missed by one check, which is the same visibility a lock released a moment earlier would give.

**Own-branch rename.** A helper `_own_refs(tree)` returns the set of ref short names to ignore for that tree: its current local branch (`git rev-parse --abbrev-ref HEAD`, empty when detached) and its configured upstream (`git rev-parse --abbrev-ref @{upstream}`, empty when none). `collisions()` drops locations in that set from `others` alongside `own = worktree:<tree>`. Other refs, including a stale branch with another slug, still collide.

**Tests.**
- Extend `test_contract_docs_name_the_allocator_and_the_check` to assert `--from-idea` in both `AGENTS.md` and `docs/README.md` (if either lacks it, the doc gains the mention in the "New work" step; that is the only non-test file touched besides `spec_numbers.py`).
- In `test_uncommitted_collision_before_start_releases_and_reallocates`, record `_reservations(cfg, wt)` in both the `before` and `after` hooks and assert separately `2 not in` and `3 in` the before-state, and that the after-state is still exactly `[3]`; keep the retry-counter and prompt assertions.

## Alternatives considered

- **Cache scans across calls with a TTL** - stale numbers are exactly the bug class SPEC-0569 fixes; per-call dedupe gets most of the saving safely.
- **Skip remote-tracking refs** - reintroduces the SPEC-0569 collision gap.
- **Keep the lock in `collisions()` but avoid mkdir** - still blocks behind allocate while running git subprocesses.
- **Ignore every ref containing the tree's file name** - hides real collisions with other branches.

## Acceptance criteria

- [ ] `AGENTS.md` and `docs/README.md` both contain `--from-idea`, and the docs guard test asserts it for both files.
- [ ] The queue test asserts after the release that reservation 2 is absent and 3 is live before the writer runs, and that the reservations are still `[3]` after the writer run.
- [ ] `allocate` on a repo whose local and remote-tracking refs share commits runs one `git ls-tree` per distinct commit and one `for-each-ref`, not one per ref, and not twice over.
- [ ] `list_reservations` and `release` run no `git ls-tree` when the store has no record for the key; results are unchanged otherwise.
- [ ] `collisions()` with a nonexistent `data_dir` neither creates `data_dir` nor `spec-reservations.lock`, and returns while another process holds the exclusive lock.
- [ ] A spec file renamed (same number, new slug) and uncommitted on the tree's own branch is not a collision; the same number under another slug on any other local or remote ref still is.
- [ ] All existing `tests/test_spec_numbers.py`, `tests/test_agentic_spec_writer.py` and `tests/test_specs*.py` tests pass unchanged apart from the two named tightened ones.
